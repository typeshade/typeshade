**Rule 8.1.** An entry point is a `const` at the top of the file or of a namespace, initialized by a stage call that wraps the entry's function: `export const vs = vertex(function vs(…) { … })`, `fragment(f)`, or `compute([x, y?, z?], f)` (change 0111, D1). The function is a function expression or an arrow function; a function expression's name, when it has one, must be the constant's, and the entry takes the constant's name. An entry method on a class must be refused.
A function declaration with a stage decorator (`@vertex export function vs(…)`) stays accepted as an entry until the release after the migration release (change 0111, Amendment 2, D5).

- Rationale: `this` is not a GPU instance, and an entry has no receiver. A call that wraps the function is the form a plain `tsc --strict` accepts; it refuses a decorator on a function declaration (TS1206). A named function expression keeps the entry's name in a stack trace and in the emit.
- Derives from: [Entry Points](https://gpuweb.github.io/gpuweb/wgsl/#entry-points); change `0111` in `changes/` (D1); surface §3 and §4.
- Enforced by: `src/compiler/ts/stage-call.ts`, which reads a stage call as the function declaration it stands for; pinned by `src/compiler/ts/stage-call.test.ts` (the emit of each pair is the decorated form's, a function expression named otherwise is refused in the compiler and in the editor, and the host face reads the call), `src/language-service/new-entry-forms.test.ts` (the editor lists the entries with their stage) and `examples/plain-typescript.test.ts`; `TS8035 CLASS_MEMBER` (`A decorator has no place on "C.k"; an entry is a top-level function.`), beside surface §7's row "`@compute` method on a class".
