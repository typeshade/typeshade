**Rule 8.1.** An entry point is a function declaration at the top of the file or of a namespace, exported or not, with exactly one stage attribute written before the declaration: `@vertex export function vs(…)`, `@fragment …`, or `@compute([x, y?, z?]) …`. The order `export @vertex function` is accepted and means the same. An entry takes its declaration's name, so `export default` on an entry must be refused with `TS8028` ("an entry takes its declaration's name; write `export function k`") (change 0130, D4, as amended by change 0140). A bare `@compute` and `@compute()` take the default size (Rule 8.7). `@vertex` and `@fragment` take no argument list: `@vertex()` and an argument on either must be refused with `TS8028`. An entry written as a `const`, an arrow function or a function expression, and an entry method on a class, must be refused; the stage calls of change 0111 are refused (Rule 6.7).

- Rationale: `this` is not a GPU instance, and an entry has no receiver. The stage marks the function, so it is the language's attribute on the declaration (Rule 1.8).
- Derives from: [Entry Points](https://gpuweb.github.io/gpuweb/wgsl/#entry-points); change `0111` (D1, replaced by change `0130`); change `0130`; change `0140`; surface §3 and §4.
