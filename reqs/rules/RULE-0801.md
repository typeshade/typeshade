**Rule 8.1.** An entry point is a function declaration at the top of the file or of a namespace, exported or not, with exactly one stage attribute written before the declaration: `@vertex export function vs(…)`, `@fragment …`, or `@compute([x, y?, z?]) …`. The order `export @vertex function` is accepted and means the same. An entry takes its declaration's name, so `export default` on an entry must be refused with `TS8028` ("an entry takes its declaration's name; write `export function k`") (change 0130, D4, as amended by change 0140). A bare `@compute` and `@compute()` take the default size (Rule 8.7). An entry written as a `const`, an arrow function or a function expression, and an entry method on a class, must be refused; the stage calls of change 0111 are refused (Rule 6.7). Appendix B records the refusals that wait for change 0140's refusing pull request.

- Rationale: `this` is not a GPU instance, and an entry has no receiver. The stage marks the function, so it is the language's attribute on the declaration (Rule 1.8).
- Derives from: [Entry Points](https://gpuweb.github.io/gpuweb/wgsl/#entry-points); change `0111` (D1, replaced by change `0130`); change `0130`; change `0140`; surface §3 and §4.
- Enforced by: the front end's entry reading in `src/compiler/ts/source-file.ts` and `decorated-form.ts`, pinned by `src/compiler/ts/stage3.test.ts` (both orders, a namespace entry, two stage attributes refused, `export default` refused) and `src/language-service/new-entry-forms.test.ts`; `TS8035` (`A decorator has no place on "C.k"; an entry is a function declaration with a stage attribute, "@vertex export function vs(…) { … }".`), beside surface §7's row "`@compute` method on a class".
