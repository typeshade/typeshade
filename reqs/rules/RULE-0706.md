**Rule 7.6.** A read of a local before it is assigned on every path must be refused (`TS8075`), by TypeScript's rule for its TS2454, with an argument an `out<T>` parameter takes counting as an assignment (Rule 8.25); every target starts a local declared with no initializer at the zero of its type.
A local that an `out<T>` argument fills first is declared with TypeScript's definite assignment, `let q!: vec2; project(p, q);`, which a plain `tsc --strict` accepts and which states the same fact, that a call fills it (change 0111, D8); the `!` changes nothing in the compiler's check, which still refuses a read of `q` that no assignment and no `out<T>` argument comes before (`TS8075`). Without the `!`, the compiler accepts the same program and a plain `tsc --strict` reports TS2454 at the call.

- Rationale: the two targets differed here, WGSL and the CPU reading zero and GLSL ES 3.00 an undefined value, and the editor already refused the read with TypeScript's TS2454 while the compiler accepted it; the refusal makes the two halves one (Rule 12.7), and the zero keeps the targets equal for any read an analysis misses.
- Derives from: change `0043` in `changes/`; change `0111` (D8); [`var` Declarations](https://gpuweb.github.io/gpuweb/wgsl/#var-decls) (zero-initialization); surface §14 and §70.
- Enforced by: `TS8075 UNASSIGNED_READ` in `src/compiler/ts/definite.ts`; the zero initializer of `localVar` in `src/core/backends/glsl.ts`; pinned by `src/compiler/ts/definite-assignment.test.ts`, which holds `TS8075` to TypeScript's TS2454 reads, and `src/compiler/ts/attribute-types.test.ts`, which refuses a read of an `out<T>` local before the call fills it.
