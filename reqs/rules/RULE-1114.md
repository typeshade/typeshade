**Rule 11.14.** Every capability of WebGPU and of WebGL2, as the sources of Appendix C enumerate them, must have exactly one status per target in the coverage table: `typed`, `raw`, `refused`, `planned`, `gap` or `n/a`. A capability with no row, or with two statuses on one target, is a defect of the table.

- Rationale: the goal is a sentence about every capability, so the table must cover every one, and one status per target is what makes the sentence checkable.
- Derives from: the request that opened this proposal; Rule 1.2; Rule 2.1.
- Enforced by: `src/core/spec-conformance/capability-coverage.test.ts` (Rule 11.15).
