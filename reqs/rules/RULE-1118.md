**Rule 11.18.** A `typed` row must name the test that verifies the capability on each target where it is `typed`; the test must read both halves where the capability is a language spelling (Rule 12.7). A `refused` row must name the rule and the portable spelling. A `planned` row must name its proposal. A `gap` row must name its issue once one is filed. An `n/a` row must name its reason.

- Rationale: a status is a claim, and a claim with no evidence is the kind of row Appendix B exists to list.
- Derives from: Rule 12.5; Rule 12.7; Appendix B's shape.
- Enforced by: `capability-coverage.test.ts`, which fails on a `typed` row whose test file does not exist, on a `refused` row with no `Rule N.M`, and on a `planned` row whose proposal file does not exist or is `withdrawn`.
