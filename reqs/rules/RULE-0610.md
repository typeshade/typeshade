**Rule 6.10.** A local `const` binds its name once and leaves what it holds as writable as TypeScript does.
A write into it (to a field, a component or an element, or by a method that writes its object) must change the value when the initializer builds one nothing else holds (`new`, an object literal, an array literal or a type's constructor, alone or with methods called on it), the declaration being emitted as a `var` from then on; it must be a write to that place when the initializer is a place: a name, a field or an element of one, or a call of a function of the file whose every `return` names one parameter (Rule 8.8, rule 1).
A `const` initialized from a place is a second name of that place, and nothing is emitted for it (Rule 8.8, change 0142).
A `const` initialized from any other call that may give an object that has a name is refused with the remedy, as `TS8099`, where the function writes an object after the declaration (Rule 8.8, rule 4), unless the program never writes an object of that type (Rule 8.8, rule 6).
A `const` nothing writes into stays WGSL's `let`.
`v`, or a field or an element of `v`, is such a write when it is handed to a parameter that its function writes (Rule 8.25).

- Rationale: `const v = new V(); v.bump()` is how TypeScript is ordinarily written, since a `const` fixes the name and not the object; nothing else holds the object `new` built, so the local is that object, and a write through it changes what TypeScript changes.
  A `const` initialized from a field or an element holds an object something else holds: TypeScript's write reaches the object both hold, so the `const` is a second name of that place and the write reaches the place (change 0142, Amendment A3, rule 1).
  A `const` initialized from a call that may give an object that has a name cannot be that place, and a copy would not show a write, so the front end refuses the declaration where the function writes an object after it, as not supported yet (change 0142, stage 2), and names the remedy.
  Before this rule every write through a `const` was refused, with `let` as the remedy.
  An object has the identity a JavaScript object has (Rule 8.8), so `const w = v` and `let w = v` make `w` a second name of `v`, always and not only where a write follows; Rule 7.2's table records both.
- Derives from: ECMAScript [`let` and `const` declarations](https://tc39.es/ecma262/#sec-let-and-const-declarations) (a `const` binding cannot be assigned again, and what it holds is not frozen); [Value Declarations](https://gpuweb.github.io/gpuweb/wgsl/#value-decls) and [`var` Declarations](https://gpuweb.github.io/gpuweb/wgsl/#var-decls); Rule 8.10; surface §26.

Read what you need from the call first, or write through the name that holds the object.`, `src/compiler/ts/lower/second-name.ts`), which also says a write through that `const` once, so that the write adds no second diagnostic; `TS8005 CONST_ASSIGN` for a write to a component of a `const` vector or matrix, which is a value (`"v" is a const, and a write to a component of it changes it.
