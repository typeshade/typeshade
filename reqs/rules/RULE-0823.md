**Rule 8.23.** A kernel function's parameter of an array with no size is the caller's array (change 0142): the body reads its elements and its `.length`, writes its elements in place, and cannot assign it whole (`TS8018`). The call reads back an array the body writes, and an array the body never writes comes back as it went in; `return` of the parameter gives the same array, or the same `Buffer`, with no copy. The author writes no qualifier, and a written `@inout` or `@out` is `TS8073` (Rule 8.25); no call fills an array with zeros. A fixed-size array parameter, `array<T, N>`, is an object too (Rule 8.8). The `.length` of such an array counts elements, so an `array<vec4f>` counts vectors (change 0068). A `Buffer` of the parameter's class, or of its scalars, is such storage too (Rule 8.21): the call reads and writes its device copy, and the host reads what the call wrote with `await buffer.read()`.
A kernel function may also make the array it returns (change 0114, S5): one `const` at the top level of its body, before its first loop and its first store, initialized by `new Float32Array(n)` (`n` zeros of `f32`) or `new Array(n).fill(v)` (`n` copies of `v`), whose element is an `f32`, an `i32` or a `u32`, and returned on every path. `n` has any number type and reads only the value parameters, their components and fields, module constants, the `.length` of an array parameter, number literals, `u32`, `i32` and `f32` of these, and top-level `const`s of these, with `+`, `-`, `*`, `/`, `%`, `min` and `max`; `v` reads the same operands. The host evaluates `n` and `v` before anything runs, with the program's arithmetic, and a length that is negative or not an integer throws a `RangeError` that names the function and the length. The body reads and writes the array's elements and reads its `.length`, as for an array parameter; the call holds the array as an array parameter of its own (the compiler's choice of representation, OD-9), checks every index against `n` as for a parameter, and resolves to it. Refused as not supported yet (`TS8099`), each with a sentence that names the form: an element of a vector or a struct; such an array in a helper or an entry; one made inside a loop, under a branch, or after a loop or a store; a length or a fill value that reads another operand; `Array.from({ length: n }, f)` with such a length; another `return`; a use of the array as a value (`out.push(v)`, a second name, an argument of a call); and a function that also takes a 2D storage texture. A result of an array with no size that is no new array stays `TS8020`.
For a read-only, non-resident array of flat scalar objects, a private WebGPU input may contain only live fields in declaration order (change 0082). Field use includes all loops and reachable helpers. Unproved uses retain the full layout. Fusion facts do not select an execution mode: an eligible ordinary call can project inputs while its face carries full-layout facts (change 0085). The CPU and WebGL2 paths, authored entry bindings, raw bytes, resident and fused calls retain their original layout. Element indexing and array length do not change.
A kernel function's texture parameter (change 0077), a `texture_2d<f32>` or a 2D storage texture, stays the caller's texture, passed by reference with no qualifier, as a `Map` and a `Set` do: the body loads it with `textureLoad`, measures it with `textureDimensions`, stores into a storage texture with `textureStore`, and cannot assign it whole.
An array parameter a loop pushes onto (change 0078) starts empty in the function, or at its held length when the call passes one (change 0094): the pushes append in the order a sequential run of the function makes them, loop by loop, iteration by iteration and statement by statement, on every tier, so a second loop that pushes onto the array appends after the first, and its `.length` is the held length (0 without one) plus the count appended, a `u32`, which may exceed the host array's length. The host array is the capacity: the call writes the elements from the held length up to `min(length, capacity) - 1` and leaves the rest as they were, and the host reads the length through the function's own `return out.length`, or in the held length's word, which the call leaves holding the new length.
A held length is `{ array, length, offset? }` (Rule 8.21): `array` is what the parameter takes otherwise, and element `offset` of `length`, a `Buffer<u32>` (change 0138, Amendment A10, confirmation item 3), holds the array's length when the call runs, as an array's `length` before ECMAScript's `push`. The call refuses, with a `TypeError` that names the function and the parameter, before anything runs: the object on an array no loop pushes onto (decision D5); a `length` that is no `Buffer<u32>`, a scratch array of a `fuse` scope or a disposed `Buffer`; an `offset` that is no whole number from 0, or is past `length`; a `length` that is another argument of the call or the `length` of another; and a `Buffer` of another owner (Rule 11.8). An object with another key is refused as a wrong array is.
A `Map` or a `Set` parameter (change 0080) is the caller's JavaScript `Map` or `Set`, passed by reference: its entries are there before the loop, and when the call resolves the entries a sequential run of the function leaves are in it. A key is added once, and its place in the order is the first `add` or `set` of it; a `Map` keeps the value of the last `set` of each key; keys compare by SameValueZero, so one `NaN` key holds every `NaN` and `-0` is `0`. The call refuses, with a `TypeError` that names the parameter, a value that is not a `Map` or a `Set` as the parameter says, and the first key or value that does not fit its type.
For a key-type `K`, the host passes strings: the call converts keys to ids before the loops and back to strings after them, preserving insertion order; a key outside the union is a `TypeError`, and `Map<string, V>` and `Set<string>` stay refused (change 0081).
A kernel function is emitted by no target, since it runs on the host's side of the call; an `array<T, N>` parameter is an object (Rule 8.8).

- Rationale: a runtime-sized array exists only in storage (Rule 12.6). A kernel function's array is the caller's array, as a JavaScript function's array parameter is, so a function that updates it writes its elements and the call writes them back; the compiler reads which arrays a body writes, so no qualifier says it (OD-5, change 0142). A write that nothing carries back is no longer a refusal: the caller's array changes, as it does in JavaScript, and the code of that refusal is retired.
