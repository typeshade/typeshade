**Rule 8.23.** A kernel function's parameter of an array with no size is the caller's storage, passed by reference: the body reads and writes its elements in place, reads its `.length`, and cannot assign it whole; whether the body writes it decides its access.
A kernel function is emitted by no target, since it runs on the host's side of the call; an `array<T, N>` parameter stays by value.

- Rationale: `render(k, 512, img)` fills `img`, which is TypeScript's own meaning of a typed-array argument, and a runtime-sized array exists only in storage (Rule 12.6), so a copy has no meaning.
- Derives from: change `0013` in `changes/`; Rule 8.8; Rule 12.6.
- Enforced by: `parseParams` and `fillFunctionBody` in `src/compiler/ts/lower/function.ts`, which take the parameter as an `inout` storage array for a kernel function and refuse it on any other (`TS8020`); `withoutKernels` in `src/core/ir/kernels.ts`, which every backend and `reflect()` read through; pinned by `src/compiler/ts/kernel-loops.test.ts`, which runs a kernel function on the CPU oracle and holds the caller's array written in place.
