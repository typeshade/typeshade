**Rule 8.23.** A kernel function's parameter of an array with no size is the caller's array (change 0142): the body reads its elements and its `.length`, writes its elements in place, and cannot assign it whole (`TS8018`). The call reads back an array the body writes, and an array the body never writes comes back as it went in; `return` of the parameter gives the same array, or the same `Buffer`, with no copy. The author writes no qualifier, and a written `@inout` or `@out` is `TS8073` (Rule 8.25); no call fills an array with zeros. A fixed-size array parameter, `array<T, N>`, is an object too (Rule 8.8). The `.length` of such an array counts elements, so an `array<vec4f>` counts vectors (change 0068). A `Buffer` of the parameter's class, or of its scalars, is such storage too (Rule 8.21): the call reads and writes its device copy, and the host reads what the call wrote with `await buffer.read()`.
A kernel function may also make the array it returns (change 0114, S5): one `const` at the top level of its body, before its first loop and its first store, initialized by `new Float32Array(n)` (`n` zeros of `f32`) or `new Array(n).fill(v)` (`n` copies of `v`, or for a struct `n` references to one object, as JavaScript's `fill` gives), whose element is an `f32`, an `i32` or a `u32`, a vector of them, or a struct whose fields are these (slice 2), and returned on every path. `n` has any number type and reads only the value parameters, their components and fields, module constants, the `.length` of an array parameter, number literals, `u32`, `i32` and `f32` of these, and top-level `const`s of these, with `+`, `-`, `*`, `/`, `%`, `min` and `max`; `v` reads the same operands, and may be a vector or a struct built of them. The host evaluates `n` and `v` before anything runs, with the program's arithmetic, and a length that is negative or not an integer throws a `RangeError` that names the function and the length. The body reads and writes the array's elements and reads its `.length`, as for an array parameter, and `.length` reads `n` on every tier, 0 included; the call holds the array as an array parameter of its own (the compiler's choice of representation, OD-9), checks every index against `n` as for a parameter, and resolves to it in the form Rule 8.21 gives an array parameter of its element: the scalar's typed array for a scalar or a vector element, a vector's components one after another (`Float32Array` for `vec4f[]`), and an array of objects for a struct, instances of its class when the module exports one. A struct fill shares one object (Amendment A8, item 4; OD-5): in the result, every element the run does not write as a whole is one object, which is the caller's own object when `v` is a struct parameter or a field of one, and each element the run writes as a whole (`out[i] = w`) is its own object, so a write on the host to a field of one unwritten element shows in every other. Where the compiler cannot prove that the run writes every element, the kernel records a written mark for each element and the host reads the marks (the compiler's choice, OD-9). A vector is a value, so a vector fill shares nothing. Refused as not supported yet (`TS8099`), each with a sentence that names the form: an element that is a matrix, a `bool`, a key or an `f64`, or a struct that holds one; such an array in a helper or an entry; one made inside a loop, under a branch, or after a loop or a store; a length or a fill value that reads another operand; a whole write of a struct element whose object the compiler cannot tell is new to that element (`out[i] = w` where `w` is a parameter, another element or a `const` declared before the loop); `Array.from({ length: n }, f)` with such a length; another `return`; a use of the array as a value (`out.push(v)`, a second name, an argument of a call); and a function that also takes a 2D storage texture. A result of an array with no size that is no new array stays `TS8020`.
The `const` may instead start empty, annotated with an array with no size of an element the made array may hold (`const out: f32[] = []`, change 0114, S5d), and grow with `out.push(v)` in the `for` and `for…of` loops of the body: a loop at the top level, a loop nested in one, or a loop under a top-level `if` whose condition reads only the operands `n` reads (change 0114, Amendment A12, form 2, Route 1). The compiler computes its capacity, the sum over the pushes of the product of the trip counts of every loop around a push (a push in an outer body counts once for each outer trip, a push in an inner body once for each inner trip of each outer trip, and a push under a branch inside a loop counts as one), where every loop's start and bound read only the operands `n` reads, and a loop under a top-level `if` counts only when the host, evaluating the condition with the program's arithmetic, finds its branch taken; the host evaluates the start and the bound with the program's arithmetic and the capacity exactly, with no wrap, before anything runs, and holds the array as an array parameter of that capacity. A capacity past 4294967295, or past what one host array of its element holds, throws a `RangeError` that names the function, the array and the capacity before anything runs, since a length past that limit is not supported yet. The pushes append as they do onto an array parameter (below), in the order of a sequential run, on every tier; `out.length` in the body reads the number pushed so far; and the call resolves to a new array of exactly the elements pushed, in the made array's form, which the caller owns. Pushes of a struct keep JavaScript's objects (Amendment A8, item 4): when every push pushes one `const` object declared at the top level of the body, which only the pushes use, the elements are one object; a push of a new object each time gives each element its own. Refused as not supported yet (`TS8099`), each with a sentence that names the loop or the form: pushes of a struct that the compiler cannot tell are one object or new ones (one object mixed with new ones, or one the body changes); a push outside every loop; a push in a `while` or `do … while`, or under a `switch`, or in a loop under a branch inside a loop, or in a loop whose branch at the top level has a condition that reads another operand; a loop whose trip count is no count from a start to a bound by a constant whole step, or whose start or bound reads another operand, the counter of a loop around it or a range the device holds included (Route 2 of A12 serves those, in a later slice); an element the made array may not hold; a read or a write of an element before the first loop; and a write the compiler cannot prove below the length in a loop that is no `for` at the top level of the body, or in a loop whose trip count the call cannot compute. The other refusals of the made array apply to it. An element of the array is read and written as JavaScript reads and writes it at that point of a sequential run (change 0114, Amendment A12, section 2): a read needs an index below the length, a write an index at most the length, and a write at the length appends as `push` does. An index the compiler proves below the length, the counter of a loop that counts up from 0 to `out.length` by 1 and that the body does not write, runs on every tier as an array parameter's does. Any other index is checked at the call on the CPU tier only (A12, Q1 (C)): the function has no GPU plan, and the reason names the access; each such write counts as one push in the capacity; and an index past what the access may reach throws a `RangeError` that names the function, the access, the index and the length, before the caller's arrays change.
For a read-only, non-resident array of flat scalar objects, a private WebGPU input may contain only live fields in declaration order (change 0082). Field use includes all loops and reachable helpers. Unproved uses retain the full layout. Fusion facts do not select an execution mode: an eligible ordinary call can project inputs while its face carries full-layout facts (change 0085). The CPU and WebGL2 paths, authored entry bindings, raw bytes, resident and fused calls retain their original layout. Element indexing and array length do not change.
A kernel function's texture parameter (change 0077), a `texture_2d<f32>` or a 2D storage texture, stays the caller's texture, passed by reference with no qualifier, as a `Map` and a `Set` do: the body loads it with `textureLoad`, measures it with `textureDimensions`, stores into a storage texture with `textureStore`, and cannot assign it whole.
An array parameter a loop pushes onto (change 0078) starts empty in the function, or at its held length when the call passes one (change 0094): the pushes append in the order a sequential run of the function makes them, loop by loop, iteration by iteration and statement by statement, on every tier, so a second loop that pushes onto the array appends after the first, and its `.length` is the held length (0 without one) plus the count appended, a `u32`, which may exceed the host array's length. The host array is the capacity: the call writes the elements from the held length up to `min(length, capacity) - 1` and leaves the rest as they were, and the host reads the length through the function's own `return out.length`, or in the held length's word, which the call leaves holding the new length.
A held length is `{ array, length, offset? }` (Rule 8.21): `array` is what the parameter takes otherwise, and element `offset` of `length`, a `Buffer<u32>` (change 0138, Amendment A10, confirmation item 3), holds the array's length when the call runs, as an array's `length` before ECMAScript's `push`. The call refuses, with a `TypeError` that names the function and the parameter, before anything runs: the object on an array no loop pushes onto (decision D5); a `length` that is no `Buffer<u32>`, a scratch array of a `fuse` scope or a disposed `Buffer`; an `offset` that is no whole number from 0, or is past `length`; a `length` that is another argument of the call or the `length` of another; and a `Buffer` of another owner (Rule 11.8). An object with another key is refused as a wrong array is.
A `Map` or a `Set` parameter (change 0080) is the caller's JavaScript `Map` or `Set`, passed by reference: its entries are there before the loop, and when the call resolves the entries a sequential run of the function leaves are in it. A key is added once, and its place in the order is the first `add` or `set` of it; a `Map` keeps the value of the last `set` of each key; keys compare by SameValueZero, so one `NaN` key holds every `NaN` and `-0` is `0`. The call refuses, with a `TypeError` that names the parameter, a value that is not a `Map` or a `Set` as the parameter says, and the first key or value that does not fit its type.
For a key-type `K`, the host passes strings: the call converts keys to ids before the loops and back to strings after them, preserving insertion order; a key outside the union is a `TypeError`, and `Map<string, V>` and `Set<string>` stay refused (change 0081).
A kernel function is emitted by no target, since it runs on the host's side of the call; an `array<T, N>` parameter is an object (Rule 8.8).
