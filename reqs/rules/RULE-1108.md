**Rule 11.8.** A kernel function's call (Rule 8.21) runs on the first tier of `configure({ prefer })` that can run it, WebGPU, WebGL2 and the CPU tier being the default order: WebGPU when the function lowers (Rule 8.22) and there is a device, the one that `configure({ limits, features })` asks for (change 0051), WebGL2 when every loop writes one array of 4-byte elements (`f32`, `i32`, `u32`) at exactly `i` and every scalar parameter is a number or a vector, each loop one fragment program into an `R32UI` target that starts out holding the array, so an iteration that writes nothing leaves its element, and the CPU tier always; a list of one tier makes that tier required, and a call no tier on the list can run throws an `Error` naming each tier's reason. A WebGPU loop runs at the workgroup size its function declares (Rule 8.22); WebGL2 and the CPU tier have no workgroup, and their results do not depend on it.
Every tier computes a reduction in the tree order (Rule 7.2).
Kernel calls run one after another in the order they were made, whether or not the caller awaits them.
The calls a `fuse` body records (Rule 11.13) run together as one item of that order, at the place `fuse` was called: the calls and the reads made after it see what they wrote.
On WebGL2 the calls of a scope run apart, each as it runs outside a scope.
`resident(value)` wraps a host value (Rule 8.21) once in a `Resident`, which holds its own copy: a call on WebGPU uploads it the first time and binds the same buffer at every call after, reading nothing back, and `await r.read()` waits for the calls made before it and returns a new copy of what it holds; `r.write(value)` replaces what it holds and `r.destroy()` releases its buffer, each after the calls made before it, or at once when none waits, a use after `destroy()` being a `TypeError`; a call that fails while nobody awaits it leaves its error on each `Resident` it writes, which `read()` throws. `resident(length, element)` makes a zeroed `Resident` of `length` numbers, `element` being `'f32'`, `'i32'` or `'u32'`, which has no element default: it holds no host copy and writes no byte to a queue when it is made; a call on WebGPU makes a zeroed storage buffer and writes no byte to it, and a call that writes it leaves the device copy the newer; `read()` returns a new array of zeros, with no host copy kept, when no call has written the handle and `write()` has not run, and otherwise downloads the device buffer once. Its refusals are `TypeError`s: a length that is not a whole number from 1 to 4294967295, an element that is not `'f32'`, `'i32'` or `'u32'`, and a first argument that is not a number when an element is given; `resident(value)` with one argument is unchanged, so `resident(8, undefined)` is refused as an element. A scratch array of a `fuse` scope (Rule 11.13) is a `Resident` the host never reads or writes: its `read()` rejects with a `TypeError` and its `write()` throws one. One `Resident` must not be two parameters of one call. The same `Resident` is a buffer of the program runtime too, bound by any draw or dispatch of a runtime on the same device, and `configure({ runtime })` puts every call on that runtime's device (Rule 11.11); a program runtime's `Texture` passed where a call takes an image is bound as it is, and a draw that falls to WebGL2 refuses it with a `TypeError`.
A host may open an owner of its calls, `createDevice()` from `typeshade/runtime` (change 0071): on the first tier of `createDevice({ prefer })` that opens, which the device reports as `tier` with each earlier tier's reason in `skipped`, on a `GPUDevice` the host hands in, or on a program runtime's device (Rule 11.11); the tiers after the one that opened stay the fallback of a call that tier cannot run. `device.array(value)` and `device.array(length, element)` make a `Resident` as `resident()` does, owned by the device; `device.release(r)` gives it back, and the device keeps it for a later `array()` of the same element and length while the pool that `poolBytes` bounds has room, the oldest released array leaving first, and frees it otherwise; a reused array of `array(length, element)` holds zeros, cleared on the device where its buffer exists. One `Resident` belongs to one owner for its life: a call takes the arrays of its own owner only, a `Resident` of another owner being a `TypeError` that names both owners, and `resident()` makes the default owner's. `device.limits` is the device's limits (change 0051), empty on a tier with none; `device.lost` resolves when the browser invalidates the WebGPU device; `device.wait()` resolves when the device has completed every plan submitted so far; `device.dispose()` waits for the plans in flight, destroys every array the device holds, each once, and the WebGPU device it requested, never a device or a runtime the host handed in, and a use after it is a `TypeError`. Two devices in one context are independent. The process-global `configure()`, `resident()` and `fuse()` describe the default owner, the one a bare call outside any `device.fuse()` body uses. An owner has a flavor of the emulated double (change 0073): `createDevice({ fp64Flavor })` takes `'float'` or `'integer'` and `device.fp64Flavor` reports it, `configure({ fp64Flavor })` sets the default owner's for the calls made after it, the default of both is `'float'`, the lowering every module ran before, and a word that is neither is a `TypeError` naming the two. A kernel call, an entry call and a draw of a module that emulates `f64` dispatch the WGSL of their owner's flavor, read at the call (Rule 8.22), the `_fp64` guard bound under `'float'` and absent under `'integer'`; a module that emulates none runs as it did, and the WebGL2 tier and the CPU tier have one form each, which the flavor does not change.
A kernel call takes a texture parameter (Rule 8.23, change 0077): a sampled `texture_2d<f32>` takes an image source or a program runtime's or a device's `Texture`, and a 2D storage texture takes a `Texture` a device made with `device.texture({ size, format, storage: true })`, of the parameter's format. `device.texture()` makes a 2D texture its owner holds, with the usages of a program runtime's texture, and `dispose()` destroys it; a texture belongs to one owner as a `Resident` does, and a call of another owner refuses it with a `TypeError` naming both. Before anything runs the call checks each texture a loop stores into at `vec2(i % W, i / W)`: `W` is at most the texture's width and the last iteration's row is inside its height, or the call is a `TypeError` naming the parameter, its size and the texels. A texture call runs on WebGPU and on the CPU tier (Rule 11.7), which reads an `ImageData` and a texture of its own memory and says why it cannot read any other; WebGL2 binds no texture parameter yet, and says so. `device.texture()` on a device with no WebGPU device makes a texture of the CPU tier's memory, of a format that tier holds, and refuses another format with a `TypeError` that names the formats.
An owner has a time budget (change 0074): `createDevice({ timeBudgetMs })` takes the time one chunk of a long kernel may take, in milliseconds, 250 by default, which `device.timeBudgetMs` reports, and a value that is not a finite number from 1 to 60000 is a `RangeError` naming the range. `device.chunkSize(key, max, min = 1)` is the units of the next chunk of `key`: `min`, capped at `max`, before a chunk of `key` was measured, so the first chunk teaches the rate; after it, the units that fit eight tenths of the budget at the learned rate, at most four times the last chunk's units, at least `min` and at least 1, and never more than `max`. A `max` or a `min` that is not a whole number of 1 or more is a `RangeError`, a `key` that is not a non-empty string a `TypeError`, and on the CPU tier, which has no watchdog, the answer is `max`. `device.chunkRates` holds, for each key a chunked plan named (Rule 11.13), a `ChunkRate`, `{ msPerUnit, chunks, longestMs, lastUnits }`, exported from `typeshade/runtime` and the root: the rate per unit is the first chunk's measured one, then the mean of the previous rate and the measured one, and a chunk counts at least one unit and at least one microsecond. The default owner, `configure()` and `fuse()`, has no budget.
A `@compute` entry's call (Rule 8.24) runs in the same order as kernel calls, and on the first tier of `configure({ prefer })` that can run it: WebGPU when there is a device, WebGL2 when there is a context and the entry reaches no texture, as a pass program over textures of 32-bit words with its barriers and atomic operations in the phased order of change 0054, so it leaves what the CPU oracle leaves, and the CPU tier when the entry reaches no barrier and no texture; a call no tier on the list can run throws, a `TypeError` naming what the entry reaches when the CPU tier refused it, an `Error` naming each tier's reason otherwise. A storage array binding with no size may be a `Resident`, bound on WebGPU as its device buffer and read back by nobody, and a call whose written bindings are all resident has a second signature, returning `void`; a `Resident` for any other binding, or as two bindings of one call, is a `TypeError`. In the body of a `fuse` scope (Rule 11.13) the call runs in the scope's plan, in the order of the plan, on the same tiers.
Every `Resident` buffer has the usage `INDIRECT` too (change 0075), so an entry call takes a `Resident<Uint32Array>` as its workgroup count (Rule 8.24). WebGPU dispatches it with `dispatchWorkgroupsIndirect` at four times the offset, uploading a host copy that is the newer and reading nothing back. The CPU tier and WebGL2 read the three counts from the host copy, brought up to date, when the call runs, and run that grid. A count with a 0 in it, or one greater than the `maxComputeWorkgroupsPerDimension` of the owner's WebGPU device (65535 where the owner holds none), runs no workgroup on every tier and throws nothing, since WebGPU's queue runs nothing for such a count and cannot report it without a read. The counts array is held to the owner of the call as a binding is.
A draw's tiers are fixed: WebGPU, then WebGL2, then the CPU tier, where a canvas keeps the tier of its first draw; a draw may read a `Resident` for a storage array with no size, and then runs in the order of kernel and entry calls, seeing what the calls before it wrote, with the handle bound as its device buffer on WebGPU and its copy brought up to date on the CPU tier; a `Resident` for any other binding is a `TypeError`.

- Rationale: a chain of calls over the same data (a particle step, a relaxation) should pay one upload and one read, not one of each per call: #252 measured the conversion of a million 32-byte structs at about 220 ms in and 1.3 s out, which residency pays once. The order of the tiers is the caller's to set, and a caller that needs the GPU says so and gets an error that names why rather than a slow answer (#252's open question 6). The calls keep their order because a queued call has no await to order it by. A GPU watchdog resets a device whose one submission runs too long (about two seconds on Windows), so a kernel that iterates inside one dispatch runs as chunks, and the owner, which has the fence, the tier and a clock, sizes them from what it measured rather than each consumer (change 0074).
