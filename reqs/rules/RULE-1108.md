**Rule 11.8.** A kernel function's call (Rule 8.21) runs on the first tier of its owner's policy that can run it (change 0085). A default-owner call uses `configure({ prefer })`, WebGPU, WebGL2 and the CPU tier being the default order: WebGPU when the function lowers (Rule 8.22) and there is a device, the one that `configure({ limits, features })` asks for (change 0051), WebGL2 when every loop writes one array of 4-byte elements (`f32`, `i32`, `u32`) at exactly `i` and every scalar parameter is a number or a vector, each loop one fragment program into an `R32UI` target that starts out holding the array, so an iteration that writes nothing leaves its element, and the CPU tier always; a list of one tier makes that tier required, and a call no tier on the list can run throws an `Error` naming each tier's reason. A WebGPU loop runs at the workgroup size its function declares (Rule 8.22); WebGL2 and the CPU tier have no workgroup, and their results do not depend on it.
A loop that pushes onto an array (change 0078) runs on WebGPU in three dispatches of one submission, count, scan and store, the scan in one workgroup of 256, and the call reads the total back for the function's result; it runs on the CPU tier when its counting step, which runs the iteration and stores nothing, would change what it computes (a second pushed array, a reduction, a scatter, a texture store, a write it reads back); WebGL2 runs none and says so. An array that two loops push onto, or whose length the stores after the loops read, has a length word on WebGPU (change 0094): the first invocation of each loop's scan starts the offsets at the length the word holds and writes the new length into it, so the second loop appends after the first and the entry that stores reads the length there; the call makes the word, a zeroed `u32`, when the caller holds none, and such a loop that runs no iteration runs its scan alone, so the length after it is known. A call that passes a held length (Rule 8.23) runs a second WGSL text on WebGPU, in which every array a loop pushes onto has its word, bound as the buffer the held length's `Resident` has on the device: the new length stays there, and a call that returns nothing reads nothing back. The CPU tier brings the held length's host copy up to date, starts the array's count at it and writes the new length into it. A loop that adds to a `Map` or a `Set` (change 0080) runs on WebGPU as a loop that pushes: each `add` or `set` pushes a record, its key and a `Map`'s value, onto a binding the call makes, `n` times the most an iteration adds long, and the call applies the records to the caller's collection in order, which gives ECMAScript's entries and insertion order; a loop that reads a `Map` or a `Set` no loop of the function adds to finds a key by a binary search over the keys the call uploads, sorted by an order word that SameValueZero makes equal for equal keys, with a `Map`'s values beside them; a loop that reads what an earlier loop of the function added searches the collection after the call has applied that loop's records, and the call uploads it once; a loop that adds after one that reads, two loops that add to one, and an `add` inside a nested loop run the function on the CPU tier, and WebGL2 runs none and says so.
A function that stores into its arrays after its loops (Rule 8.22, change 0094) runs the stores on WebGPU in an entry of one invocation, which the call dispatches after the loops' dispatches, in the plan's one submission inside a `fuse` scope: the entry combines each variable a loop reduced with what the GPU folded, as the result's tail does, and stores into the arrays it binds, so a store into a `Resident` stays on the device, and a call that returns nothing reads nothing back; a function with no loop is that entry alone. WebGL2 draws the loops and then runs the stores on the CPU tier over its host copies, and runs no function with no loop; the CPU tier runs the function as written. A store whose index is past the array's end is dropped on every tier. Such a function runs on the CPU tier, and says why, when a statement after its loops reaches an array a loop scatters into or reads a texture, and when it takes a `Map` or a `Set`; on a device that allows a stage fewer storage buffers than the entry that stores binds (every array, the partials of each loop that reduces and the length words), the call runs on the next tier and says why.
A loop whose range the device holds (Rule 8.22, change 0094) maps on WebGPU from counts that no host reads: the call makes a trip buffer with the usages `STORAGE` and `INDIRECT`, eight `u32`s for each such loop, and frees it once the call has run. Before each such loop, a range entry of one invocation runs the statements before the loop over the bound arrays, computes the start and the trip count as the call computes a range on the host, and writes the start's bits, the trip count and the workgroup count `[x, y, 1]` of the loop's entry into the buffer, a count past 65,535 workgroups spilling into `y`; the loop's entry reads its start and trip count there, from a read-only binding of the same buffer, and the call dispatches it with `dispatchWorkgroupsIndirect` from those counts, so a trip count of 0 dispatches no workgroup. The range entry of a loop runs after the dispatches of the loops before it, in the same submission as its loop, and in the plan's one submission inside a `fuse` scope; nothing is read back. The entry guards each write by the array's `arrayLength`, so a write past the end is dropped. WebGL2 computes such a range on the CPU tier over its host copies, brought up to date, once the draws before it have written them, and draws the iterations whose `i` lies inside the array the loop writes; the CPU tier runs the function as written, the guarded writes dropping a write past the end. On a device that allows a stage fewer storage buffers than such a loop's entries bind (every array, the trip buffer and the length words), the call runs on the next tier and says why.
Every tier computes a reduction in the tree order (Rule 7.2).
Kernel calls run one after another in the order they were made, whether or not the caller awaits them.
The calls a `fuse` body records (Rule 11.13) run together as one item of that order, at the place `fuse` was called: the calls and the reads made after it see what they wrote.
On WebGL2 the calls of a scope run apart, each as it runs outside a scope.
`resident(value)` wraps a host value (Rule 8.21) once in a `Resident`, which holds its own copy: a call on WebGPU uploads it the first time and binds the same buffer at every call after, reading nothing back, and `await r.read()` waits for the calls made before it and returns a new copy of what it holds; `r.write(value)` replaces what it holds and `r.destroy()` releases its buffer, each after the calls made before it, or at once when none waits, a use after `destroy()` being a `TypeError`; a call that fails while nobody awaits it leaves its error on each `Resident` it writes, which `read()` throws. `resident(length, element)` makes a zeroed `Resident` of `length` numbers, `element` being `'f32'`, `'i32'` or `'u32'`, which has no element default: it holds no host copy and writes no byte to a queue when it is made; a call on WebGPU makes a zeroed storage buffer and writes no byte to it, and a call that writes it leaves the device copy the newer; `read()` returns a new array of zeros, with no host copy kept, when no call has written the handle and `write()` has not run, and otherwise downloads the device buffer once. Its refusals are `TypeError`s: a length that is not a whole number from 1 to 4294967295, an element that is not `'f32'`, `'i32'` or `'u32'`, and a first argument that is not a number when an element is given; `resident(value)` with one argument is unchanged, so `resident(8, undefined)` is refused as an element. A scratch array of a `fuse` scope (Rule 11.13) is a `Resident` the host never reads or writes: its `read()` rejects with a `TypeError` and its `write()` throws one. One `Resident` must not be two parameters of one call. The same `Resident` is a buffer of the program runtime too, bound by any draw or dispatch of a runtime on the same device, and `configure({ runtime })` puts default-owner calls on that runtime's device (Rule 11.11); a program runtime's `Texture` passed where a call takes an image is bound as it is, and a draw that falls to WebGL2 refuses it with a `TypeError`.
A host may open an owner of its calls, `createDevice()` from `typeshade/runtime` (change 0071): on the first tier of `createDevice({ prefer })` that opens, which the device reports as `tier` with each earlier tier's reason in `skipped`, on a `GPUDevice` the host hands in, or on a program runtime's device (Rule 11.11); the tiers after the one that opened stay the fallback of a call that tier cannot run. `device.array(value)` and `device.array(length, element)` make a `Resident` as `resident()` does, owned by the device; `device.release(r)` gives it back, and the device keeps it for a later `array()` of the same element and length while the pool that `poolBytes` bounds has room, the oldest released array leaving first, and frees it otherwise; a reused array of `array(length, element)` holds zeros, cleared on the device where its buffer exists. One `Resident` belongs to one owner for its life: a call takes the arrays of its own owner only, a `Resident` of another owner being a `TypeError` that names both owners, and `resident()` makes the default owner's. `device.limits` is the device's limits (change 0051), empty on a tier with none; `device.lost` resolves when the browser invalidates the WebGPU device; `device.wait()` resolves when the device has completed every plan submitted so far; `device.dispose()` waits for the plans in flight, destroys every array the device holds, each once, and the WebGPU device it requested, never a device or a runtime the host handed in, and a use after it is a `TypeError`. Two devices in one context are independent. The process-global `configure()`, `resident()` and `fuse()` describe the default owner. An ordinary kernel, compute-entry or draw call selects the unique owner of its resident arrays and device-created textures; an indirect workgroup count participates too (change 0085). Plain host values select no owner, so a call with none uses the default owner. Mixing distinct owners, including an explicitly default-owned resident, is a `TypeError` naming both before execution. A scope fixes its calls' owner. Owner inference preserves validation, copy-back, ordering and fallback; it creates no global current device. Disposal completes captured calls and refuses new calls after it starts. A draw with owned resources joins the call queue. An inferred device owner's draw follows its tier policy; a draw with no device-owned resource retains the fixed WebGPU, WebGL2, CPU order. A canvas retains its first drawing tier, and refuses an owner whose policy excludes it; switching WebGPU owners rebuilds device-specific drawing resources. An owner has a flavor of the emulated double (changes 0073 and 0085). `createDevice({ fp64Flavor })` and `configure({ fp64Flavor })` take `'auto'`, `'float'` or `'integer'`, defaulting to `'auto'`. Automatic selection uses the executing device's identity, its retained creation adapter or the actual WebGL context, with the existing user-agent fallback; it requests no unrelated adapter. Apple or Metal signals select `'integer'`; other or unknown GPU signals select `'float'`, and CPU selects `'float'`. Unknown signals do not establish hardware precision. Explicit flavors remain overrides. `device.fp64Flavor` reports a resolved flavor, and `configure({})` restores automatic selection. An unknown setting is a `TypeError` naming the three choices. `DeviceOptions` encodes mutually exclusive `prefer`, `device` and `runtime` sources; conflicting combinations fail TypeScript checking and runtime validation. A kernel call, an entry call and a draw of a module that emulates `f64` dispatch the WGSL of their owner's flavor, read at the call (Rule 8.22), the `_fp64` guard bound under `'float'` and absent under `'integer'`; a module that emulates none runs as it did, and the WebGL2 tier and the CPU tier have one form each, which the flavor does not change.
A kernel call takes a texture parameter (Rule 8.23, change 0077): a sampled `texture_2d<f32>` takes an image source or a program runtime's or a device's `Texture`, and a 2D storage texture takes a `Texture` a device made with `device.texture({ size, format, storage: true })`, of the parameter's format. `device.texture()` makes a 2D texture its owner holds, with the usages of a program runtime's texture, and `dispose()` destroys it; a texture belongs to one owner as a `Resident` does, and a call of another owner refuses it with a `TypeError` naming both. Before anything runs the call checks each texture a loop stores into at `vec2(i % W, i / W)`: `W` is at most the texture's width and the last iteration's row is inside its height, or the call is a `TypeError` naming the parameter, its size and the texels. A texture call runs on WebGPU and on the CPU tier (Rule 11.7), which reads an `ImageData` and a texture of its own memory and says why it cannot read any other; WebGL2 binds no texture parameter yet, and says so. `device.texture()` on a device with no WebGPU device makes a texture of the CPU tier's memory, of a format that tier holds, and refuses another format with a `TypeError` that names the formats.
`createDevice({ limits, features })` declares instance-local WebGPU requirements (change 0085), independent of `configure()`. Omitted requirements are empty. Values are validated and copied before requesting an adapter. A requested device negotiates the named limits and features; an unsupported requirement or a failed WebGPU request records its reason in `skipped` and tries only the remaining tiers in that owner's `prefer`. A WebGPU-only preference refuses that failure. WebGL2 and CPU fallbacks have no WebGPU capabilities. A supplied device or runtime must already enable every requested feature and meet each named limit, with minimum limits checked in the opposite direction to maximum limits. Missing capabilities are a `TypeError`, and no adapter is requested to validate a supplied device. No owner changes the default owner's request or another owner's native capabilities. `configure()` remains the default-owner compatibility API, including its existing refusal of late capability changes.
An owner has a time budget (change 0074): `createDevice({ timeBudgetMs })` takes the time one chunk of a long kernel may take, in milliseconds, 250 by default, which `device.timeBudgetMs` reports, and a value that is not a finite number from 1 to 60000 is a `RangeError` naming the range. `device.chunkSize(key, max, min = 1)` is the units of the next chunk of `key`: `min`, capped at `max`, before a chunk of `key` was measured, so the first chunk teaches the rate; after it, the units that fit eight tenths of the budget at the learned rate, at most four times the last chunk's units, at least `min` and at least 1, and never more than `max`. A `max` or a `min` that is not a whole number of 1 or more is a `RangeError`, a `key` that is not a non-empty string a `TypeError`, and on the CPU tier, which has no watchdog, the answer is `max`. `device.chunkRates` holds, for each key a chunked plan named (Rule 11.13), a `ChunkRate`, `{ msPerUnit, chunks, longestMs, lastUnits }`, exported from `typeshade/runtime` and the root: the rate per unit is the first chunk's measured one, then the mean of the previous rate and the measured one, and a chunk counts at least one unit and at least one microsecond. The default owner, `configure()` and `fuse()`, has no budget.
A `@compute` entry's call (Rule 8.24) runs in the same order as kernel calls, and on the first tier of its selected owner's policy that can run it: WebGPU when there is a device, WebGL2 when there is a context and the entry reaches no texture, as a pass program over textures of 32-bit words with its barriers and atomic operations in the phased order of change 0054, so it leaves what the CPU oracle leaves, and the CPU tier when the entry reaches no barrier and no texture; a call no tier on the list can run throws, a `TypeError` naming what the entry reaches when the CPU tier refused it, an `Error` naming each tier's reason otherwise. A storage array binding with no size may be a `Resident`, bound on WebGPU as its device buffer and read back by nobody, and a call whose written bindings are all resident has a second signature, returning `void`; a `Resident` for any other binding, or as two bindings of one call, is a `TypeError`. In the body of a `fuse` scope (Rule 11.13) the call runs in the scope's plan, in the order of the plan, on the same tiers.
Every `Resident` buffer has the usage `INDIRECT` too (change 0075), so an entry call takes a `Resident<Uint32Array>` as its workgroup count (Rule 8.24). WebGPU dispatches it with `dispatchWorkgroupsIndirect` at four times the offset, uploading a host copy that is the newer and reading nothing back. The CPU tier and WebGL2 read the three counts from the host copy, brought up to date, when the call runs, and run that grid. A count with a 0 in it, or one greater than the `maxComputeWorkgroupsPerDimension` of the owner's WebGPU device (65535 where the owner holds none), runs no workgroup on every tier and throws nothing, since WebGPU's queue runs nothing for such a count and cannot report it without a read. The counts array is held to the owner of the call as a binding is.
A draw follows its inferred device owner's tier policy, or the fixed WebGPU, WebGL2, CPU order with no device-owned resource. A canvas keeps the tier of its first draw; a draw may read a `Resident` for a storage array with no size, and then runs in the order of kernel and entry calls, seeing what the calls before it wrote, with the handle bound as its device buffer on WebGPU and its copy brought up to date on the CPU tier; a `Resident` for any other binding is a `TypeError`.

Entry-call constants (Rule 8.24, change 0084) select pipelines cached per device, entry, normalized values and owner-selected fp64 flavor. The generated CPU closure receives the same values and resolved invocation shape, and its reachable workgroup arrays have their selected lengths. Device workgroup limits are checked before uploads; specialized CPU calls use WebGPU's portable minimum workgroup limits. The CPU barrier refusal remains. WebGL2 pins ordinary constants in its prebuilt program and refuses non-default workgroup shapes or workgroup-array lengths.

`Device.info` (change 0083) is a deeply frozen, JSON-serializable snapshot of the opened device: `build`, `tier`, and nullable `webgpu` and `webgl` sections. It describes the opened device, not each call's effective tier or the aggregate `FuseReport.tier`. WebGPU identity comes from that device's `adapterInfo`, its retained creation adapter, or stays unavailable; no unrelated adapter is requested. Enabled features and device limits are copied, not adapter maxima. WebGL strings come only from the actual context, with nullable debug strings. CPU has no GPU section. The snapshot remains readable as historical metadata after loss or disposal, without claiming current availability. It contains no native handles, persistent device identifier, browser user agent, storage or automatic telemetry.

- Rationale: a chain of calls over the same data (a particle step, a relaxation) should pay one upload and one read, not one of each per call: #252 measured the conversion of a million 32-byte structs at about 220 ms in and 1.3 s out, which residency pays once. The order of the tiers is the caller's to set, and a caller that needs the GPU says so and gets an error that names why rather than a slow answer (#252's open question 6). The calls keep their order because a queued call has no await to order it by. A GPU watchdog resets a device whose one submission runs too long (about two seconds on Windows), so a kernel that iterates inside one dispatch runs as chunks, and the owner, which has the fence, the tier and a clock, sizes them from what it measured rather than each consumer (change 0074).
