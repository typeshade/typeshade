**Rule 1.7.** Every form the surface takes beyond TypeScript must be one the language service can give TypeScript's checker so that the checker serves the editor (Rule 12.7): projected to valid TypeScript, or kept as a form TypeScript parses, whose grammar report the language service drops and whose content it checks with the compiler's own check of that form (a stage attribute, Rule 8.1, `@workgroup_size`, Rule 8.22, or a parameter qualifier `@inout` or `@out`, Rule 8.25).
This is the language service's work: the source is not required to be valid TypeScript, and no TypeScript tool's acceptance of the source is a criterion (Rule 1.8).
A form neither path can carry is not added.

- Rationale: as the language borrows TypeScript's forms and extends a few (`Array<T, N>`, the stage attributes), the language service keeps TypeScript's checker only while every extension has a TypeScript form it can be read as, projected or kept as TypeScript parses it. A checker of TypeShade's own would be a second implementation of the language; calling the compiler's own check of a kept form is not one.

- Enforced by: review; for the forms on the surface today, the parity tests Rule 12.7 names.
