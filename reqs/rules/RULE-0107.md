**Rule 1.7.** Every form the surface takes beyond TypeScript must be one the editor can project to valid TypeScript, so that TypeScript's checker serves the editor (Rule 12.7).
A parameter qualifier, `@inout` or `@out` (Rule 8.25), is kept as TypeScript parses it: the language service drops TypeScript's grammar report on it (TS1206) and checks it with the compiler's own check (change 0137).
A form no projection can carry is not added.

- Rationale: as the language borrows TypeScript's forms and extends a few (`Array<T, N>`), the editor keeps TypeScript's checker only while every extension has a TypeScript form it can be read as. A checker of TypeShade's own would be a second implementation of the language.
- Derives from: `changes/0100-typescript-meaning.md` (section 2, decision D8).
- Enforced by: review; for the forms on the surface today, the parity tests Rule 12.7 names.
