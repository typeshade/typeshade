**Rule 8.28.** A call must not copy a struct or a fixed-size array that its callee only reads when the argument is a place: a `let` local, a module variable, an element or a field of a binding, a reference the caller holds (a parameter it writes through or reads in place), or a field or an element of one of those.
The arguments it covers are a method's or a getter's object, the object of a base's body called through `super`, and a struct or an array argument of a function of the file whose parameter carries no qualifier; an entry's parameters are not covered.
The callee reads the caller's place for the whole call: on WGSL through a pointer, `ptr<AS, T>` with `&place` at the call (`ptr<storage, T, read>` for a `read` binding), and one copy of the function for each address space its calls use; on GLSL ES 3.00, for a module-scope place (a uniform block, an element of a `read` storage binding, a module variable), through a copy of the function that reads the place by its name, each index the place is reached through passed as a parameter and evaluated once at the call.
A local on GLSL ES 3.00, where no reference only reads, a `const` local, which is a value on both targets, and an argument that is no place stay a copy taken at the call.
So does a place that can change while the callee runs, which is a place the callee or a function it calls writes by its name, a place another argument of the call is a reference the callee writes through to, and memory other invocations share (a workgroup variable, an element of a `read_write` storage binding) when the callee or a function it calls runs a barrier.
On GLSL ES 3.00 a reference a callee writes through (Rules 8.10 and 8.25) to a module variable is also reached through a copy of the function that writes the variable by its name.

- Rationale: in TypeScript an object argument and a method's `this` are the object itself, so an author who writes `items[i].area()` writes a read of the fields `area` reads, not a load of the element whole; a struct parameter is a value on both targets, so the copy is the compiler's to avoid, and a driver that inlines the call does not remove every one: an array field read at a dynamic index needs the copy in memory, a storage element loads every field nothing proves dead, a chain of methods copies at each level, and GLSL ES 3.00 rebuilt a uniform block from its members at each call and refused a method on an emulated storage element.
  The callee reads the place for as long as it runs, where the copy was taken once at the call, and the two read one value unless the place changes during the call; the three routes that can change it keep the copy, so no program computes another value, and the first two are also the calls WGSL's alias analysis refuses.
  A copy of the function that names the global is the form a target without pointers has, and the one Tint gives a pointer parameter when it writes HLSL or MSL.
- Derives from: change `0103` in `changes/`; [Function calls](https://gpuweb.github.io/gpuweb/wgsl/#function-calls), [Alias analysis](https://gpuweb.github.io/gpuweb/wgsl/#alias-analysis) and the language extension `unrestricted_pointer_parameters` in the WGSL specification; the GLSL ES 3.00 specification, section 6.1.1.
- Enforced by: the pointer-space pass in `src/core/backends/wgsl-ptr.ts` and the GLSL-local pass in `src/core/backends/glsl-global-places.ts`, pinned by `src/compiler/ts/reference-reads.test.ts`, which compiles each place and each route that keeps the copy, holds the three CPU paths to one value for them, and reads the language service's diagnostics on the same sources.
