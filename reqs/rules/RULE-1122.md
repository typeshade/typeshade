**Rule 11.22.** No source construct opts a function into a floating-point rewrite; change 0131 removed the `numerics` contract of change 0107. The optimizer must apply a rewrite that a NaN, an infinity or the sign of a zero can observe (`x * 0` to `0`, `x - x` to `0`, `mix(a, b, 0)` to `a`) only where it proves that the operands are in the domain where the rewrite gives the CPU oracle's bits, with one exception: `x + 0` and `0 + x` to `x` (decision 4 of change 0107), which ignores the sign of a zero, as WGSL §15.7.2 permits. It must apply no rewrite that changes the rounding of `f32` arithmetic (reassociation, distribution, factoring).

- Rationale: the GPU computes what the oracle computes (`docs/dx.md`), and a rewrite the compiler can prove exact needs nothing from the author. A rewrite that cannot be proved exact changes a result, so neither the author nor the compiler opts into it.
- Derives from: change 0107 (removed by 0131); `changes/0131-remove-numerics.md`; Rule 1.3; Rule 4.4; Rule 11.20.
- Enforced by: `src/core/passes/opt/algebraic.ts`, and `src/core/passes/opt/algebraic.test.ts`, which asserts that `x * 0`, `x - x`, `mix(a, b, 0)` and `mix(a, b, 1)` are kept (`Verifies: Rule 11.22`).
