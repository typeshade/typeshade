**Rule 11.11.** The program runtime, `typeshade/runtime`, loads a manifest (Rule 11.10) and runs its entries on WebGPU, on the host's device or on one it requests with the features the programs need, or on WebGL2, on the host's context or on one it makes, in the order `createRuntime({ prefer })` gives and reports as `rt.tier` (change 0054); on WebGL2 it runs a compute entry as the pass program the manifest carries (`gl.computes`) and never builds one, refuses an entry with none with a `TypeError` that gives the reason, and draws with the vertex and fragment programs the manifest carries (`gl.vertices`, `gl.draws`), keeping WebGPU's conventions: a texture's row 0 is the top row a pass draws, a fragment's `position` and a stored depth are WebGPU's, and a pass into the canvas is turned over onto the screen; it refuses with a `TypeError` what WebGL2 has no form of (a multisampled, layered, 3D or storage texture, a `GPUCommandEncoder`, a pass's `GPURenderPassEncoder`, targets that blend or mask apart); its module closure must hold no file of `src/compiler/` and no package, and its bundle must stay within the size budget `scripts/bundle-budget.json` records.
The load-time emitter, `repack` from `typeshade/emit`, emits a manifest again from the portable IR it carries, under the options the manifest records (`emit`), with a variant the build did not write (`console`), and must refuse a manifest with no IR and an IR another package version wrote, naming both versions; its module closure must hold no file of `src/compiler/` and no package, within its own budget; the runtime takes it as `createRuntime({ emit })` and never imports it, so `load(m, { console: true })` of a manifest with no recorded variant records through it, and is refused, naming the remedy, without it.
It builds each pipeline's layout from the manifest, the bindings the pipeline's entries reach each visible to the stages that reach them and each texture laid out by the sample type the manifest gives it, and never `layout: 'auto'`; it makes each shader module from the text the manifest holds and binds the bindings the manifest lists, the `_fp64` guard among them where it lists one, so a program packed under emit options (Rule 11.10) runs as it was packed; it binds by the names the source declares, packing a plain host value (Rule 8.21) by the binding's layout, and refuses an unknown name, a missing binding and a value of the wrong shape with a `TypeError` naming the entry, its line and the binding; its `load`, `compute`, `render`, `draw` and `dispatch` carry the bindings a typed manifest gives each entry, so `tsc` refuses the same mistakes and an unknown entry name at the argument, and an untyped manifest takes any bindings (change 0030); it creates each pipeline with the override values the host gives it by name, the same to every stage, one pipeline for each set of values, and refuses with a `TypeError` a name the manifest does not declare, naming the program's overrides, and a value its type cannot hold, naming the override and what its type takes; it refuses a manifest of another schema, a feature the device lacks, and a colour target whose format cannot hold the entry's output there; it reads a texture back as bytes (every uncompressed colour format and `depth32float`, rows tightly packed) or as numbers (a float, `unorm` or `snorm` format and `depth32float`; an integer format is refused with a `TypeError` that names `read()`), recording and submitting the copy before the read awaits anything, so that a read reads what was submitted before the call; a frame that repeats its shapes creates no GPU object; and the `console.*` calls of a program loaded to record reach the host's sink or its console after the submit that ran them, and that submit resolves to what each console buffer it read back held (its entry, the lines it kept and the calls that did not fit), where a runtime given a sink prints nothing, the warning for the calls that did not fit included, since its host takes the count.

- Rationale: a host that develops dynamically needs a runtime, and an application must not ship the compiler to have one: the front end is 1.4 MB gzipped with TypeScript, the runtime about 13 KB on WebGPU, and its WebGL2 tier 15 KB more, which loads only where it runs; a boundary a bundler infers from one `sideEffects` line is not a boundary, so the check reads the imports.
