**Rule 11.11.** The program runtime, `typeshade/runtime`, loads a manifest (Rule 11.10) and runs its entries on WebGPU, on the host's device or on one it requests with the features the programs need; its module closure must hold no file of `src/compiler/` and no package, and its bundle must stay within the size budget `scripts/bundle-budget.json` records.
The load-time emitter, `repack` from `typeshade/emit`, emits a manifest again from the portable IR it carries, with a variant the build did not write (`console`), and must refuse a manifest with no IR and an IR another package version wrote, naming both versions; its module closure must hold no file of `src/compiler/` and no package, within its own budget; the runtime takes it as `createRuntime({ emit })` and never imports it, so `load(m, { console: true })` of a manifest with no recorded variant records through it, and is refused, naming the remedy, without it.
It builds each pipeline's layout from the manifest, the bindings the pipeline's entries reach each visible to the stages that reach them, and never `layout: 'auto'`; it binds by the names the source declares, packing a plain host value (Rule 8.21) by the binding's layout, and refuses an unknown name, a missing binding and a value of the wrong shape with a `TypeError` naming the entry, its line and the binding; it creates each pipeline with the override values the host gives it by name, the same to every stage, one pipeline for each set of values, and refuses with a `TypeError` a name the manifest does not declare, naming the program's overrides, and a value its type cannot hold, naming the override and what its type takes; it refuses a manifest of another schema, a feature the device lacks, and a colour target whose format cannot hold the entry's output there; a frame that repeats its shapes creates no GPU object; and the `console.*` calls of a program loaded to record reach the host's sink or its console after the submit that ran them.

- Rationale: a host that develops dynamically needs a runtime, and an application must not ship the compiler to have one: the front end is 1.4 MB gzipped with TypeScript, the runtime about 10 KB; a boundary a bundler infers from one `sideEffects` line is not a boundary, so the check reads the imports.
- Derives from: changes `0025` (section 2) and `0028` in `changes/`; issue #335 (decision 1); Rule 11.10.
- Enforced by: `createRuntime` and `RuntimeImpl` in `src/runtime/runtime.ts`, `ProgramImpl` in `src/runtime/program.ts` and `src/runtime/resources.ts`; the boundary by `scripts/bundle-boundary.ts`, in CI's `typecheck + unit` job; pinned by `src/runtime/runtime.test.ts` against a recording device (creation per frame, layouts, each refusal's text, the override values each stage is created with and the pipeline cache's key on them, the console's events, a draw, a `Resident` both layers bind uploaded once, one device for both layers, a `Texture` as a call's image), and on WebGPU by the compile gate's program tier (`scripts/entry-calls-page.ts`), which dispatches every compute entry of the examples from its module's manifest and holds each written value to the call's; and by the user journeys' harness (`journeys/_harness.mjs`), which runs every journey's compute and render run on WebGPU through `typeshade/runtime` as the packed tarball ships it, imported in the page with no bundler, its console lines and dropped count included, and a run's override values set by name on its pipeline (`journeys/overrides/`), each result held to the CPU oracle's run of the module with the values as the overrides' defaults; and by the engine journey (`journeys/engine/`), a host engine on the runtime's public exports alone, two materials that share a camera and lights, a shadow pass, a render to texture and 60 frames, which the harness refuses on any other import or any WebGPU call of its own, and whose frames after the first make no GPU object, its last frame held to a reference computed in plain JavaScript.
