**Rule 11.11.** The program runtime, `typeshade/runtime`, loads a manifest (Rule 11.10) and runs its entries on WebGPU, on the host's device or on one it requests with the features the programs need; its module closure must hold no file of `src/compiler/` and no package, and its bundle must stay within the size budget `scripts/bundle-budget.json` records.
It builds each pipeline's layout from the manifest, the bindings the pipeline's entries reach each visible to the stages that reach them, and never `layout: 'auto'`; it binds by the names the source declares, packing a plain host value (Rule 8.21) by the binding's layout, and refuses an unknown name, a missing binding and a value of the wrong shape with a `TypeError` naming the entry, its line and the binding; it refuses a manifest of another schema, a feature the device lacks, and a colour target whose format cannot hold the entry's output there; a frame that repeats its shapes creates no GPU object; and the `console.*` calls of a program loaded to record reach the host's sink or its console after the submit that ran them.
The load-time emitter, `typeshade/emit`'s `repack`, must build from a manifest's portable IR the manifest `packModule` builds from the module with the same options, byte for byte, and must refuse IR another version of the package wrote, naming both versions; its module closure must hold no file of `src/compiler/` and no package, within its own budget, and the runtime never imports it: a load that needs the program emitted again, `load(program, { console: true })` of a manifest without the recorded variant, calls the emitter the host gave `createRuntime({ emit })`, and is refused with a `TypeError` when there is none or the manifest carries no IR.

- Rationale: a host that develops dynamically needs a runtime, and an application must not ship the compiler to have one: the front end is 1.4 MB gzipped with TypeScript, the runtime about 10 KB; a boundary a bundler infers from one `sideEffects` line is not a boundary, so the check reads the imports. A choice that can only be made where the program runs, the console of one session of a deployed build, needs the shader text emitted again, which the IR and the backends do without the front end; the IR is written with the sharing, the `-0` and the resolved calls plain JSON would lose, since the emitters read them, and it is no stable format, so only the version that wrote it reads it.
- Derives from: change `0025` in `changes/` (sections 2 and 5); issue #335 (decision 1); Rule 11.10.
- Enforced by: `createRuntime` and `RuntimeImpl` in `src/runtime/runtime.ts`, `ProgramImpl` in `src/runtime/program.ts` and `src/runtime/resources.ts`; `repack` in `src/emit.ts` over `src/core/ir/portable.ts`; the boundary of both by `scripts/bundle-boundary.ts`, in CI's `typecheck + unit` job; pinned by `src/runtime/runtime.test.ts` against a recording device (creation per frame, layouts, each refusal's text, the console's events, a draw, a `Resident` both layers bind uploaded once, one device for both layers, a `Texture` as a call's image, a program the emitter records although its build did not, and the emitter's refusals), by `src/emit.test.ts` and `src/core/ir/portable.test.ts` over every example (the manifest, and the WGSL, GLSL, reflection and console variant through the IR's JSON, with a fixture for each thing plain JSON loses and the version refused), and on WebGPU by the compile gate's program tier (`scripts/entry-calls-page.ts`), which dispatches every compute entry of the examples from its module's manifest and holds each written value to the call's; and by the user journeys' harness (`journeys/_harness.mjs`), which runs every journey's compute and render run on WebGPU through `typeshade/runtime` as the packed tarball ships it, imported in the page with no bundler, its console lines and dropped count included; and by the engine journey (`journeys/engine/`), a host engine on the runtime's public exports alone, two materials that share a camera and lights, a shadow pass, a render to texture and 60 frames, which the harness refuses on any other import or any WebGPU call of its own, and whose frames after the first make no GPU object, its last frame held to a reference computed in plain JavaScript.
