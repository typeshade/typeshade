**Rule 8.18.** A function declared at the top of the file or of a namespace whose parameter has a function type, written out (`f: (x: f32) => f32`) or through a type alias of one, takes a function: it is compiled once for each set of functions its calls hand it, as a generic function is once for each set of type arguments (Rule 8.9), and in each copy a call of the parameter calls the function handed over (`apply_sq`, `apply_run_f`).
A call hands a function over by its name (a module function, a local function, or a parameter of function type of the function the call is in) or as an arrow function or a function expression written in the call, which is a local function of the calling body (Rule 8.17) and takes its parameter types, and its return type where it writes none, from the parameter's type.
What the function handed over captures, the copy takes as parameters too and passes on, by reference where the function writes it.
A function handed over takes the parameter's types and returns its type, or any type where the parameter's returns `void`, whose value is not used; an arrow function may leave parameters off at the end, as TypeScript allows, and one whose body is an expression and whose type returns `void` runs the expression as a statement.
Inside the function that takes it, a parameter of function type may only be called or handed on to another such parameter.
A fold's function (`any(xs, (x) => x > k)`, `zip(xs, ys, (a, b) => a * b)`) is handed over the same way, its types read off the arrays, and an arrow function whose return type nothing gives returns what its body does.
A function type anywhere else (a return, a field, a variable), a parameter of function type on a method, a constructor, an accessor, a local function or an entry point, an argument that would choose a function at run time (`c ? f : g`), and a function whose copies would never end (one that hands itself a function it builds anew each time) must be refused.

- Rationale: TypeScript code hands functions to functions all the time: a callback to a loop helper, a predicate to a search, an operator to a fold.
  The GPU has no function value, but every call names the function it hands over, so each call reaches exactly one function, and a copy for each is what the program means; the copies are a generic function's instances by another key, and the captures, the TDZ and the cycle check are Rule 8.17's and Rule 8.4's.
  Before this rule a function type was "Unsupported type syntax" and an arrow function written as an argument "Unsupported expression".
- Derives from: ECMAScript [function objects](https://tc39.es/ecma262/#sec-ecmascript-function-objects) (a function is a value a call hands over); TypeScript's contextual typing of a function expression and its rule that a function with fewer parameters is assignable; Rule 8.4; Rule 8.9; Rule 8.17; surface §14.
- Enforced by: `TS8003 TYPE_MISMATCH` for a function that does not fit (`"add" takes 2 argument(s), and "(x: f32) => f32" passes 1, so it cannot be "f" of "apply".`), `TS8099` for a choice at run time (`"f" of "apply" takes a function, which a call hands over by its name or as an arrow function written there; "c ? sq : cube" would choose one at run time, and a shader has no function value to choose with.`), `TS8020 FUNCTION_SHAPE` for a parameter of function type where none may be, `TS8002` for a function type anywhere else, and `TS8031 RECURSION` for copies without end; pinned by `src/compiler/ts/higher-order.test.ts`, which holds WGSL, GLSL ES 3.00, the CPU oracle, the codegen and the debugger to one value for each form; `examples/higher-order.shade.ts` in the compile gate.
