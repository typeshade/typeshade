**Rule 6.6.** An entry point's inputs and outputs are explicit parameters and return values. A built-in value carries `builtin<N>`, whose type WGSL gives (`builtin<"clip_distances", array<f32, N>>` writes its type); every other input or output is user-defined, and the compiler gives it its location, which `location<n, T>` may state. The builtin name must be one WGSL defines for that stage and direction (change 0111, D2; change 0135).
Each attribute type means its value type: `pos: builtin<"position">` is a `vec4` to the compiler and to the editor, the type WGSL gives `position`, and `uv: location<0, vec2>` is a `vec2`. A written type that WGSL fixes, `builtin<"vertex_index", u32>`, is the migration form: it must compile with a `TS8028` warning that names `builtin<"vertex_index">` and `tshc migrate` in the release that ships change 0135, and the release after it refuses the written type (decision D1.2); a written type that is not WGSL's is `TS8003`. `builtin<"clip_distances">`, the one name whose type the author chooses, is `TS8003`.
The other attributes of an input or an output are an object type of options. On a built-in value the options are the second argument, `builtin<"position", { invariant: true }>` (D1.3). On a user-defined value they are the third argument of `location<n, T, O>`, so a value that states an option writes its location: `location<1, u32, { interpolate: "flat" }>`, `location<0, vec4, { blend_src: 1 }>` (change 0111, D7; change 0135, D2.3).
A written `n` is always the location. Where a user-defined value stands decides what it is and the location the compiler gives it when none is written (change 0135, D2.1):

| Where the value stands                                                                      | What it is             | Its location when none is written                                                                                                                                           |
| ------------------------------------------------------------------------------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A vertex entry's parameter, or a field of one                                               | A vertex attribute     | The lowest number no written location of that entry holds, in declaration order (the order Rule 6.8 packs the buffer in)                                                    |
| A field of a struct that a vertex entry returns                                             | A value between stages | The lowest number no written location of that struct holds, in declaration order. The scope is the struct, so a struct has one set of locations wherever it is used         |
| A fragment entry's input (a field of a struct no vertex entry returns, or a bare parameter) | A value between stages | The location the field of the same name has in the vertex results of the program. Refused (`TS8010`) when no vertex result has the name, or two give it different locations |
| A fragment entry's result, or a field of it                                                 | A render target        | The lowest number no written location of that entry holds, in declaration order; a bare result is location 0                                                                |
| A compute entry's parameter, or a field of one                                              | Refused                | None: `TS8029`, since a compute entry has no user-defined input                                                                                                             |

A fragment input that is a field of the struct a vertex entry returns has that struct's locations. A value between stages is linked by its name, as GLSL ES 3.00 links a varying.
In the mixed case each struct keeps its written numbers: with `interface A { pos: builtin<"position">; uv: location<0, vec2>; n: vec3 }` and `interface B { pos: builtin<"position">; n: location<0, vec3> }`, `A.n` is 1, the lowest number no written field of `A` holds, and `B.n` stays 0, as written. If `B` is a fragment input and writes no number on `n`, `B.n` takes the location `n` has in the vertex results; with `A` the only one, that is 1.
An entry I/O struct may be a `class`, an `interface` or a `type` (Rule 6.9), and a field of one writes its attribute in its type where it writes one (a user-defined input or output may leave its location to the compiler), and needs no initializer and no `!`; a written `!` is accepted and changes nothing, and the language service sets `strictPropertyInitialization: false` in the TypeShade program, since an entry I/O field is filled by the stage that produces it, not by an initializer.
No attribute decorator is written on an entry's parameter or on a field of an entry I/O struct: `@builtin("...")` or `@location(n)` there stays accepted with a `TS8028` warning until the release that refuses it (change 0111, D5), and the language service hides TypeScript's TS1206 on it only while `compile()` warns. A parameter qualifier on a function of the file is no entry I/O attribute (Rule 8.25).

- Rationale: an implicit stage input hides a dependency, and the input stays an explicit parameter or field. WGSL refuses an entry I/O member with no attribute, and the emitted WGSL keeps an explicit attribute on each one: that requirement binds the emitted module and not the TypeShade source (OD-1, Rule 1.1). The compiler knows the type of a built-in value and can count a location, so the author writes neither (OD-3). An input or an output is a value that flows in or out, so its attribute, when it is written, is part of its type (Rule 1.8, OD-5).
