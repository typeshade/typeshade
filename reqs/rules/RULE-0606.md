**Rule 6.6.** An entry point's inputs and outputs are explicit parameters and return values; every parameter and every field of an entry I/O struct must carry its attribute in its type, `builtin<"...", T>` or `location<n, T>`, and the builtin name must be one WGSL defines for that stage and direction (change 0111, D2).
Each attribute type means its value type `T`: `pos: builtin<"position", vec4>` is a `vec4` to the compiler and to TypeScript. The other attributes of an input or an output are a third type argument, an object type of options: `location<1, u32, { interpolate: "flat" }>`, `builtin<"position", vec4, { invariant: true }>`, `location<0, vec4, { blend_src: 1 }>` (D7).
An entry I/O struct may be a `class`, an `interface` or a `type` (Rule 6.9), and a field of one carries its attribute in its type and takes no initializer; a `class` field with no initializer takes `!` (`pos!: builtin<"position", vec4>`), which a plain `tsc --strict` requires.
The decorated form, `@builtin("...")` or `@location(n)` on a parameter or a field, stays accepted until the release after the migration release (change 0111, Amendment 2, D5), and reads as the type form does.

- Rationale: an implicit stage input hides a dependency, and WGSL refuses an entry I/O member with no attribute. A type carries the attribute because a plain TypeScript compiler refuses a decorator on a parameter of a function (TS1206), and a `"use typeshade"` file is TypeScript that an ordinary toolchain accepts (change 0111).
- Derives from:
  - [Shader Interface](https://gpuweb.github.io/gpuweb/wgsl/#shader-interface);
  - [Inter-stage Input and Output Interface](https://gpuweb.github.io/gpuweb/wgsl/#stage-inputs-outputs), whose definition of a stage input reads "each datum is either a built-in input value, or a user-defined input";
  - its subsection [Input-output Locations](https://gpuweb.github.io/gpuweb/wgsl/#input-output-locations), which carries the two requirements ("each user-defined input and output must have an explicitly specified IO location"; "each structure member in the entry point IO must be one of either a built-in value, or assigned a location", each a shader-creation error);
  - [`builtin`](https://gpuweb.github.io/gpuweb/wgsl/#builtin-attr) and [`location`](https://gpuweb.github.io/gpuweb/wgsl/#location-attr);
  - change `0111` in `changes/` (D2, D7);
  - surface §3.
- Enforced by:
  - `src/compiler/ts/attribute-types.ts`, which reads each attribute type as the decorators it stands for, so every check below reads both forms; pinned by `src/compiler/ts/attribute-types.test.ts` (a `class`, an `interface` and a `type` give the decorated form's WGSL and GLSL ES 3.00, and the editor reports nothing) and `examples/plain-typescript.test.ts` (a plain `tsc --strict` over every example);
  - `TS8024 BUILTIN_NAME` and `TS8025 BUILTIN_STAGE` for the builtin name and its stage;
  - `TS8029 STRUCT_FIELD_MISSING_ATTR` for a field of an entry I/O struct;
  - nothing at the front end for a bare parameter: `export const fs = fragment(function fs(p: vec4): vec4 { … })` compiles and reaches the WGSL text as `fn fs(p: vec4<f32>)` with no attribute, which WGSL refuses;
  - the GLSL writer alone, which reports it as a `TS8015` warning on a render module (`entry 'fs' input 'p' has neither @location nor @builtin`) and not at all on a compute-only module (Appendix B).
