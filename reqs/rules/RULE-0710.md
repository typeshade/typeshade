**Rule 7.10.** `T | undefined` is an optional value: a value of `T` that may be absent, which the compiler carries as the value and a `bool` that says whether the value is there, the same on every target (change 0088).
`T` is what a function-scope struct field may hold: a scalar, a vector, a matrix, an emulated `f64` or `vecNf64`, an array with a size, a struct or a key type; a union that repeats `undefined` is the same type, as TypeScript flattens it.
`T | undefined` for a texture, a sampler, an atomic, an array with no size, a `Map`, a `Set`, `void` or an optional must be refused (`TS8002`), and so must `null` anywhere, with `T | undefined` named as the spelling to write.
An optional value may be a local, with or without a type annotation; a parameter of a function that is no entry point, of a method or of a local function; the result of such a function, written or inferred (Rule 8.19); and a parameter or the result of a function-typed parameter (Rule 8.18).
A struct field, an array element, a binding, a module variable, a module constant, an override, an enum member, a `Map` value, a `Record` value, an entry point's parameter and an entry point's result must be refused (`TS8002`), each in one sentence that names the position; an optional has no host value (Rule 8.21).
`undefined` written where an optional is expected is the absent value, the zero of `T` and `false`; a value of `T` written there is present, that value and `true`; a `let` of an optional type with no initializer starts absent, on every target; `undefined` anywhere else must be refused (`TS8003`).
The compiler must follow TypeScript's narrowing of a local or a parameter read by its name, for these forms: `v === undefined`, `v !== undefined`, `v == undefined` and `v != undefined`, in either operand order and through `!`; the conditions of `if`, `?:`, `&&`, `||`, `while` and `for`; an early `return`, `break`, `continue` or `discard`; an assignment or an initializer, after which `v` is present when the value is a `T` and absent when it is `undefined`; and `v ??= d`, after which `v` is present.
Inside a local function or an arrow function, a `const` keeps its narrowing, and a `let` or a parameter keeps it only when nothing assigns it after the closure, as TypeScript keeps them.
A narrowed read of `v` is `v.value`; a read of an optional where a `T` is needed that nothing narrowed must be refused (`TS8003`), in TypeScript's TS18048 place (Rule 12.7), with the test and the fallback to write; a user type guard, an aliased condition, `typeof v === "undefined"` and `switch (true)` are not followed, and each is a recorded divergence (Rule 7.2).
`v ?? d` is `v`'s value where `v` is present and `d` otherwise, `d` evaluated only then (Rule 7.9), and is optional where `d` is; `o?.f`, `o?.xy` and `o?.[i]` are an optional of the member; `v === x` with `x` a `T` is `v.present && v.value == x`, `v === w` with two optionals is `true` when both are absent, and both apply only where `===` applies to `T` (Rule 7.1); `v ??= d` assigns `d` where `v` is absent.
A value read twice by a lowering (`f(x) ?? d` reads the flag and the value) is bound to a temporary ahead of its statement, and refused where no statement can take it (`TS8099`).
An optional as a condition (`if (v)`, `v && …`, `!v`), the assertion `v!`, an optional call (`o?.m()`, `f?.()`), a bare `return;` in a function with an optional result, and a function with no written result that returns `undefined` and no value must be refused, each with the edit to write.

- Rationale: a TypeScript author writes "no value" as `undefined`, and before this rule TS8002 asked the author to carry a `bool` by hand; libraries invented a sentinel value instead, which no checker tests (TypePlot's `1e20`, TypeCV's `1e30`), and `changes/0088-optional-values.md` records four curve visibility defects that came from that gap.
  The flag is a `bool` field of an ordinary struct, which every target and the CPU oracle already carry, so the IR gains no node, nothing depends on NaN (which WGSL lets an implementation assume absent, surface §44), and an analysis gap can at worst miss a refusal: an absent value reads the zero the compiler stored, on every target.
  The positions are the ones no layout reaches: WGSL forbids a `bool` in host-shareable memory, a struct field or an array element would change a layout `reflect()` reports (Rule 6.8), and an entry's IO has no `bool` interstage form.
  The editor's TypeScript checker already types and narrows `T | undefined`, so the compiler follows the same forms (decision D2) and the two halves stay one vocabulary (Rule 12.7); the forms it does not follow are recorded so that the refusal names the test to write.
  The number of this rule, surface §76 and the example id are decision D9 of the proposal.
