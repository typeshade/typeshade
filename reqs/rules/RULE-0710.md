**Rule 7.10.** `T | undefined` is an optional value: a value of `T` that may be absent, which the compiler carries as the value and a `bool` that says whether the value is there, the same on every target (change 0088).
`T` is what a function-scope struct field may hold: a scalar, a vector, a matrix, an emulated `f64` or `vecNf64`, an array with a size, a struct or a key type; a union that repeats `undefined` is the same type, as TypeScript flattens it.
`T | undefined` for a texture, a sampler, an atomic, an array with no size, a `Map`, a `Set`, `void` or an optional must be refused (`TS8002`), and so must `null` anywhere, with `T | undefined` named as the spelling to write.
An optional value may be a local, with or without a type annotation; a parameter of a function that is no entry point and no kernel function, of a method or of a local function; the result of such a function, written or inferred (Rule 8.19); a parameter or the result of a function-typed parameter (Rule 8.18); and, in function scope, a field of a class, an interface or a type literal (a parameter property included) and an element of an array with a size, `array<T | undefined, N>`, where function scope means the struct or the array is the type of a local, a parameter, a function's result or a function-typed parameter's parameter or result, or a field or an element of one of these (change 0093, decision D1).
An enum member, a `Map` value and a `Record` value must be refused (`TS8002`), each in one sentence that names the position; a binding, a module variable, a module constant, an override, an entry point's parameter, an entry point's result (an IO struct) and a kernel function's parameter (a storage array's element, a `Map` or `Set` value) that hold an optional directly, or through a field or an element, must be refused (`TS8002`) at the declaration, in one sentence that names the position and, through a struct or an array, the field or the element that holds it (change 0093, decision D1); an optional, a struct with an optional field, an array of optionals and an optional parameter have no host value (Rule 8.21).
A field `f?: T` is the same type as `f: T | undefined`, and an object literal may omit it, the omitted field absent (change 0093, decision D3); `f?: T` and `x?: T` whose `T` an optional may not hold must be refused (`TS8002`), as `T | undefined` is.
`undefined` written for a field or an element, in an object literal, in a constructor argument, in an array literal or in an assignment (`h.n = undefined`), is the absent value, a `T` written there is present, a class field with no initializer starts absent in `new C()`, and a class field with an initializer starts as the initializer says (change 0093, decision D4); a field read `h.n` and an element read `xs[i]` are optional values and take every form of this rule.
Each internal struct is declared before the first struct of the module that holds it and after the struct its `T` names, and one no declared struct holds after every declared struct, on every target (change 0093, decision D11).
`undefined` written where an optional is expected is the absent value, the zero of `T` and `false`; a value of `T` written there is present, that value and `true`; a `let` of an optional type with no initializer starts absent, on every target; `undefined` anywhere else must be refused (`TS8003`).
A parameter `x?: T` of a function that is no entry point and no kernel function, of a method, of a static function, of a constructor, of a local function, of a function-typed parameter's type (Rule 8.18) and of an arrow function written as an argument declares `x` as `T | undefined` in the body; a call may omit it, and the omitted argument is the absent value, filled where the call is as a default is (surface §14), or may write `undefined` for it; a call with too few arguments counts an optional parameter as one with a default (`TS8019`); an integer literal handed to an `i32 | undefined` takes the `i32` first (change 0093, decisions D5 and D6).
`x?: T` on an entry point, whose parameters come from the pipeline, and on a kernel function, whose parameters come from the host, `x?: T = d` (TypeScript's TS1015) and a required parameter after an optional one (TypeScript's TS1016) must be refused (`TS8020`), each in one sentence that names the edit, since the compiler reads no checker (Rule 12.7).
The compiler must follow TypeScript's narrowing of a local or a parameter read by its name, and of a member path rooted at one, `h.n` or `h.a.n` (change 0093, decision D2), for these forms: `v === undefined`, `v !== undefined`, `v == undefined` and `v != undefined`, in either operand order and through `!`; the conditions of `if`, `?:`, `&&`, `||`, `while` and `for`; an early `return`, `break` or `continue`; an assignment or an initializer, after which `v` is present when the value is a `T` and absent when it is `undefined`; and `v ??= d`, after which `v` is present.
Inside a local function or an arrow function, a `const` keeps its narrowing, and a `let` or a parameter keeps it only when nothing assigns it after the closure, as TypeScript keeps them; a bare `discard` (Rule 7.7) does not end a path for the walk, since TypeScript's flow does not know it, so a read after `if (v === undefined) { discard; }` is refused in both halves.
A member path is cleared, and read un-narrowed, after an assignment to a prefix of the path or to the root (`h = …`, `h.a = …`), after a compound assignment, `++` or `--` on the path, a prefix or the root, and after a call that takes the root by reference: `f(h)` where `f` is a function of the file whose parameter at that index is `@inout` or `@out` (Rule 8.25), and `h.m()` where `m` is a method of a class of the file that writes through `this` (Rule 8.10) or a setter; inside a local function or an arrow function a path keeps no narrowing, since TypeScript keeps one there only for a `readonly` field, which the walk does not read, and an element access `xs[i]` is not narrowed, with a literal index either; each of the two is a recorded divergence (Rule 7.2), and the refusal of an element read names the copy to test, `const x = xs[i]; if (x !== undefined)` (change 0093).
A narrowed read of `v` is `v.value`, and of a path `h.n.value`; a read of an optional where a `T` is needed that nothing narrowed, a name, a path, an element, a call or any other expression, must be refused (`TS8003`), in TypeScript's TS18048 place (Rule 12.7), with the test and the fallback to write, at a `return`, a declaration, an assignment, a compound assignment and a builtin's or a constructor's argument as at an operator or a call (change 0093); a user type guard, an aliased condition, `typeof v === "undefined"` and `switch (true)` are not followed, and each is a recorded divergence (Rule 7.2).
`v ?? d` is `v`'s value where `v` is present and `d` otherwise, `d` evaluated only then (Rule 7.9), and is optional where `d` is; `o?.f`, `o?.xy` and `o?.[i]` are an optional of the member; `v === x` with `x` a `T` is `v.present && v.value == x`, `v === w` with two optionals is `true` when both are absent, and both apply only where `===` applies to `T` (Rule 7.1); `v ??= d` assigns `d` where `v` is absent.
A value read twice by a lowering (`f(x) ?? d` reads the flag and the value) is bound to a temporary ahead of its statement, and refused where no statement can take it (`TS8099`).
An optional as a condition (`if (v)`, `v && …`, `!v`), the assertion `v!`, an optional call (`o?.m()`, `f?.()`), a bare `return;` in a function with an optional result, a path that ends such a function's body without a `return`, and a function with no written result that returns `undefined` and no value must be refused, each with the edit to write.

- Rationale: a TypeScript author writes "no value" as `undefined`, and before this rule TS8002 asked the author to carry a `bool` by hand; libraries invented a sentinel value instead, which no checker tests (TypePlot's `1e20`, TypeCV's `1e30`), and `changes/0088-optional-values.md` records four curve visibility defects that came from that gap.
  The flag is a `bool` field of an ordinary struct, which every target and the CPU oracle already carry, so the IR gains no node, nothing depends on NaN (which WGSL lets an implementation assume absent, surface §44), and an analysis gap can at worst miss a refusal: an absent value reads the zero the compiler stored, on every target.
  The positions are the ones no layout reaches: WGSL forbids a `bool` in host-shareable memory, a struct field or an array element in a binding would change a layout `reflect()` reports (Rule 6.8), and an entry's IO has no `bool` interstage form; in function scope a struct field and an array element reach no layout, so change 0093 allows them there, with the lowering change 0088 already had as the field's or the element's type, and moves the refusal to the position that cannot hold the flag, which names the field.
  An optional parameter is where a TypeScript author writes a signature's "no value": the default that meant "none", which change 0088 left as the remedy, was the sentinel moved to the signature (change 0093, Alternatives (e)); the declaration order of decision D11 is one every target, the oracle and a reader can rely on, since GLSL ES 3.00 needs a struct declared before its use.
  The editor's TypeScript checker already types and narrows `T | undefined`, so the compiler follows the same forms (decision D2) and the two halves stay one vocabulary (Rule 12.7); the forms it does not follow are recorded so that the refusal names the test to write.
  The number of this rule, surface §76 and the example id are decision D9 of the proposal; the examples are `examples/optional-values.shade.ts` and, for the positions of change 0093, `examples/optional-fields.shade.ts` (its decision D10), which the compile gate compiles on Tint and WebGL2 and whose suite, `examples/shade-examples.test.ts`, is the evidence for them once its `Verifies` tag names this rule.
