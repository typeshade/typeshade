**Rule 5.1.** An integer-written literal must take the integer type the position around it declares. An unannotated function-local `let` initialized by such a literal, by a constant of no fixed type that is one, or by `+`, `-`, `*` and `/` over those, and an unannotated module variable, static field that code writes (surface §24, Rule 8.13) or class field (Rule 8.14) initialized by integer-written literals and `+`, `-`, `*` and `/` over them, must take its type from every place it reaches: an operand of an arithmetic operator, a comparison or an equality beside a typed peer; an argument of a builtin beside a typed argument; an argument of a vector, matrix or array constructor; an arm of a conditional or of `select`; a field of an object literal; an operand of a bitwise or shift operator; an index; a `switch` selector; an assignment or a compound assignment from a typed value; a `return` in a function whose result type is declared; an argument of a declared parameter; the uses of a loop counter that starts at it; and another such value. A bitwise operand with no typed peer, a shift, an index and a `switch` selector ask for an integer of no kind, which is `i32` unless another use says `u32` or a written operand does not fit an `i32`. The compiler must solve all values of the module together, so that the result does not depend on source order. Resolve the local, callee and receiver by their declarations, including through nested scopes and inherited members; an override supplies its own signature. Uses that require `i32` and `u32` must be refused with the annotation remedy, and an integer use beside a float use must be refused where the float use stands. Where no use decides, the value must be an `f32`: that is the compiler's choice, and no default type is part of the language. The result of a function whose callers decide it (Rule 8.19) takes its type from the uses of each call in the same way, an `f32` use included. A `/` over a call of such a function must be refused where some call of the function asks an integer, whichever copy that call takes, so that the meaning of a division does not depend on another line. A `/` or a `/=` whose operands are all integers by inference, such a `let`, variable, field or call among them, must be refused as the `/` over a constant below is. The counter of a counted `for` keeps the type Rule 7.5 gives it, and the counter of a `for` that is not counted is such a `let`. A `/` over the counter of a `for` that is not counted, where no use gives that counter a type, must be refused as the `/` over a constant below is: the counter was an `i32` before change 0134 (the owner's decision of 2026-11-11 in the record of change 0134). The default type of a counted `for`'s counter must not decide the type of such a `let` that its start or its bound reads: it asks an integer of no kind, so the `let`'s other uses decide it. A function that writes no result type and returns a value over a function-local constant must return the type that value had before change 0134, where the constant took the integer type of its declared uses. An unannotated `const` whose initializer is written numbers, and a unary minus, `+`, `-`, `*`, `/` and `%` over written numbers and such constants, must be a constant of no fixed type: at module scope, in a function, or as a static field that no code writes. Its value is the ECMAScript value of the initializer. Each read of it must take the type that the written number would take in the same place, and a conversion (`u32(K)`) must convert the written number. A read that takes `f32` names the emitted `f32` declaration, and a read of another type writes the value. A value that comes from such a constant must carry that origin through every expression and binding: an operator, a builtin (`Math.*` and `select` included), `as`, `!`, a conditional, a member, a derived constant, a `let` or a pattern binding (one that a closure or a local function captures included), the start of a loop counter, and the result of a function, a method, a getter or a closure that writes no result type and returns such a value; it loses the origin only where it passes a declared type, an annotation, a declared parameter, field or result, a conversion, or a typed constructor (`vec3u(…)`, `vec2<u32>(…)`). A generic parameter declares no type. A variable initialized by written numbers alone declares no type either, so `(k + w) / 2` with `let w = 3` carries the origin of `k`. A `/` or `/=` whose operands have no declared type, one of which carries the origin of a constant that some read makes an integer (a conversion to `i32` or `u32` and a read in a file that imports it included), must be refused, unless a float-written literal or a float-written constant takes part in an operand, which makes a float division. The quotient's own read is not another read (Amendment A4 of change 0134): `let j: u32 = K / 2` is `4u` with `const K = 8`, as the written `8 / 2` is. A loop counter whose start carries such an origin must keep the type it had before change 0134, as a counter bounded by one does: the type of the constant's emitted declaration, or, for a function-local constant, the integer type its declared uses give it. A start through a `let` or a function result takes the type this rule gives that value, the `f32` sentence included, until items 1 and 3 of change 0134 are implemented. A `/` over a tree of written integers whose quotient is no integer (`(1 | 2) / 2`) must be refused as the `/` over a constant is (a module constant whose root is `|`, `&` or `^` over written integers is one tree, and so is the result of a function with no written result that returns one, or of a generic function whose result is its argument), except where a position that states an integer type reads it, which truncates it toward zero (`let j: i32 = (5 | 0) / 2` is 2), and where a comparison beside a peer that states no type or an `f32` reads it, which reads the exact value (a comparison beside a typed `i32` or `u32` is refused with a verified edit, the owner's decision of 2026-11-12); a variable whose type its uses decide states no type. A tree whose root bit operator reads a written number only a `u32` holds is that `u32`'s bits (`3000000000 | 0` is 3000000000): beside a typed `u32`, `+`, `-`, `*`, `&`, `|`, `^`, `<<` and `~` read those bits, which agree with TypeScript's value modulo 2^32, and every other operation whose result differs between the bits and TypeScript's value (`/`, `%`, a comparison, `max`, `min`, `clamp`, `abs`, `sign`, `f32()`, `>>` by an amount that is no written number, `/=`, `%=` and `>>=`, and an exported function's result), also through a binding, `?:`, `select`, a function's result, a generic function's result, a module `let`, arithmetic over a written number, a compound assignment and a plain assignment to a variable with no written type, must be refused with a verified edit, `u32(…)` or, where the value flows to an `i32` or into `f32()`, `i32(…)`, and the declaration with its type for an assignment's target or a constant of no fixed type (none for a constant of another file, and none where no form compiles in a module with this one refusal); an annotation ends the origin (the owner's decisions of 2026-11-12, "이대로" and D2). A compound assignment is no position that states a type for its right side, so a quotient there is refused as in the written-out form. An exported constant keeps the `f32` its importers read, as an exported function's result does (Amendment A5), and an importer names no edit that lands in another file. Every edit a refusal names, a `>>`'s and a value form's included, is named only where it compiles with the module's other edits. A refusal that names no edit offers no wrap where the structure shows that the wrap would not choose the division (an `f32(…)` wrap read by a bit operator, an integer wrap of a divisor whose integer quotient is 0, a `u32(…)` wrap read by a unary minus, an operand that is a `?:` with one typed arm, a constant's sentence over a division that holds a tree), and says what is true instead (the owner's decision of 2026-11-13). A conversion the author writes on an operand, also inside its arithmetic (`(1 | 2) / (i32(2) + 1)`), states its type, and the `/` is that type's division; a builtin carries its arguments' origin. The refusal must name one edit, whose type the structure of the quotient's use decides: the constant declared with the type an integer position asks, the `/` with each such value converted, or, for a `/=`, the variable declared with its type (`let y: f32 = k`). An exported function's result, in every export form, is the `f32` the host reads, and decides a quotient that flows there. The edits of every refused `/` of the module must be made at once and the program compiled, and the edits named only where that adds no error; one more set may be compiled, and no more than two a module. Where they do not compile together, no refusal of the module names an edit: each names the operands to wrap and the types its positions take, or the variable to declare with a type (the owner's decision of 2026-11-12, Amendment A6 of change 0134). A mismatch around the `/` is the refusal said again, so the mistake is one diagnostic (Rule 12.4).

- Rationale: this is WGSL's abstract-integer rule, read from every place a number reaches, so that an author writes a number as a number (`docs/owner-decisions.md` OD-7). The `f32` where nothing decides is the type such a value always had on this surface, so no program that compiled computes another value.
