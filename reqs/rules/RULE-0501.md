**Rule 5.1.** An integer-written literal must take the integer type the position around it declares. An unannotated function-local `let` initialized by such a literal takes `i32` or `u32` when declared uses require that one type for the local: direct calls to declared, nongeneric functions, constructor and instance or static method arguments, and explicitly typed initialization or simple assignment. A simple assignment can take the type of its destination or of a right-hand side that declares its type independently of the local. Resolve the local, callee and receiver by their declarations, including through nested scopes and inherited members; an override supplies its own signature. A concrete member parameter independent of generic arguments can establish a demand; an unresolved generic parameter or circular inference cannot. Conflicting concrete scalar types must be refused with an annotation or cast remedy. Where no integer type is established, the literal must be an `f32`. An unannotated `const` whose initializer is written numbers, and `+`, `-`, `*` and `/` over written numbers and such constants, must be a constant of no fixed type: at module scope, in a function, or as a static field that no code writes. Its value is the ECMAScript value of the initializer. Each read of it must take the type that the written number would take in the same place, and a conversion (`u32(K)`) must convert the written number. A read that takes `f32` names the emitted `f32` declaration, and a read of another type writes the value. A value that comes from such a constant must carry that origin through every expression and binding: an operator, a builtin (`Math.*` and `select` included), `as`, `!`, a conditional, a member, a derived constant, a `let`, the start of a loop counter, and the result of a function, a method, a getter or a closure that writes no result type and returns such a value; it loses the origin only where it passes a declared type, an annotation, a declared parameter, field or result, or a conversion. A `/` or `/=` whose operands have no declared type, one of which carries the origin of a constant that some read makes an integer (a conversion to `i32` or `u32` and a read in a file that imports it included), must be refused, unless a float-written literal or a float-written constant takes part in an operand, which makes a float division. The quotient's own read is not another read: `let j: u32 = K / 2` is `4u` with `const K = 8`, as the written `8 / 2` is. A loop counter whose start carries such an origin must keep the type it had before change 0134, as a counter bounded by one does: the type of the constant's emitted declaration, or, for a function-local constant, the integer type its declared uses give it. The refusal must name one edit that compiles where the quotient stands: the constant declared with the type an integer position asks, or the `/` with each such value converted.

- Rationale: this is WGSL's abstract-integer rule narrowed to the positions where a type is stated, and the `f32` default is the surface's history rather than WGSL's rule.
- Derives from: [Abstract Numeric Types](https://gpuweb.github.io/gpuweb/wgsl/#abstract-types) and [Conversion Rank](https://gpuweb.github.io/gpuweb/wgsl/#conversion-rank); surface §13.
