**Rule 5.1.** An integer-written literal must take the integer type the position around it declares. An unannotated function-local `let` initialized by such a literal, by a constant of no fixed type that is one, or by `+`, `-`, `*` and `/` over those, and an unannotated module variable, static field that code writes (surface §24, Rule 8.13) or class field (Rule 8.14) initialized by integer-written literals and `+`, `-`, `*` and `/` over them, must take its type from every place it reaches: an operand of an arithmetic operator, a comparison or an equality beside a typed peer; an argument of a builtin beside a typed argument; an argument of a vector, matrix or array constructor; an arm of a conditional or of `select`; a field of an object literal; an operand of a bitwise or shift operator; an index; a `switch` selector; an assignment or a compound assignment from a typed value; a `return` in a function whose result type is declared; an argument of a declared parameter; the uses of a loop counter that starts at it; and another such value. A bitwise operand with no typed peer, a shift, an index and a `switch` selector ask for an integer of no kind, which is `i32` unless another use says `u32` or a written operand does not fit an `i32`. The compiler must solve all values of the module together, so that the result does not depend on source order. Resolve the local, callee and receiver by their declarations, including through nested scopes and inherited members; an override supplies its own signature. Uses that require `i32` and `u32` must be refused with the annotation remedy, and an integer use beside a float use must be refused where the float use stands. Where no use decides, the value must be an `f32`: that is the compiler's choice, and no default type is part of the language. The result of a function whose callers decide it (Rule 8.19) takes its type from the uses of each call in the same way, an `f32` use included. A `/` or a `/=` whose operands are all integers by inference, such a `let`, variable, field or call among them, must be refused as the `/` over a constant below is. The counter of a counted `for` keeps the type Rule 7.5 gives it, and the counter of a `for` that is not counted is such a `let`. A `/` over the counter of a `for` that is not counted, where no use gives that counter a type, must be refused as the `/` over a constant below is: the counter was an `i32` before change 0134 (the owner's decision of 2026-11-11 in the record of change 0134). The default type of a counted `for`'s counter must not decide the type of such a `let` that its start or its bound reads: it asks an integer of no kind, so the `let`'s other uses decide it. A function that writes no result type and returns a value over a function-local constant must return the type that value had before change 0134, where the constant took the integer type of its declared uses. An unannotated `const` whose initializer is written numbers, and a unary minus, `+`, `-`, `*`, `/` and `%` over written numbers and such constants, must be a constant of no fixed type: at module scope, in a function, or as a static field that no code writes. Its value is the ECMAScript value of the initializer. Each read of it must take the type that the written number would take in the same place, and a conversion (`u32(K)`) must convert the written number. A read that takes `f32` names the emitted `f32` declaration, and a read of another type writes the value. A value that comes from such a constant must carry that origin through every expression and binding: an operator, a builtin (`Math.*` and `select` included), `as`, `!`, a conditional, a member, a derived constant, a `let` or a pattern binding (one that a closure or a local function captures included), the start of a loop counter, and the result of a function, a method, a getter or a closure that writes no result type and returns such a value; it loses the origin only where it passes a declared type, an annotation, a declared parameter, field or result, a conversion, or a typed constructor (`vec3u(…)`, `vec2<u32>(…)`). A generic parameter declares no type. A variable initialized by written numbers alone declares no type either, so `(k + w) / 2` with `let w = 3` carries the origin of `k`. A `/` or `/=` whose operands have no declared type, one of which carries the origin of a constant that some read makes an integer (a conversion to `i32` or `u32` and a read in a file that imports it included), must be refused, unless a float-written literal or a float-written constant takes part in an operand, which makes a float division. The quotient's own read is not another read (Amendment A4 of change 0134): `let j: u32 = K / 2` is `4u` with `const K = 8`, as the written `8 / 2` is. A loop counter whose start carries such an origin must keep the type it had before change 0134, as a counter bounded by one does: the type of the constant's emitted declaration, or, for a function-local constant, the integer type its declared uses give it. A start through a `let` or a function result takes the type this rule gives that value, the `f32` sentence included, until items 1 and 3 of change 0134 are implemented. The refusal must name one edit that compiles where the quotient stands: the constant declared with the type an integer position asks, the `/` with each such value converted, or, for a `/=`, the variable declared with its type (`let y: f32 = k`). Where no such edit compiles, the program holds another mistake: the refusal names the edit that adds fewest errors, and a mismatch around the `/` stays only where that edit leaves it, so the mistake is one diagnostic (Rule 12.4).

- Rationale: this is WGSL's abstract-integer rule, read from every place a number reaches, so that an author writes a number as a number (`docs/owner-decisions.md` OD-7). The `f32` where nothing decides is the type such a value always had on this surface, so no program that compiled computes another value.
