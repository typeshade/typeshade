**Rule 5.1.** An integer-written literal must take the integer type the position around it declares. An unannotated function-local `let` initialized by such a literal, or by `+`, `-`, `*` and `/` over such literals, must take its type from every place it reaches: an operand of an arithmetic operator, a comparison or an equality beside a typed peer; an argument of a builtin beside a typed argument; an argument of a vector, matrix or array constructor; an arm of a conditional or of `select`; a field of an object literal; an operand of a bitwise or shift operator; an index; a `switch` selector; an assignment or a compound assignment from a typed value; a `return` in a function whose result type is declared; an argument of a declared parameter; and another such value. A bitwise operand with no typed peer, a shift, an index and a `switch` selector ask for an integer of no kind, which is `i32` unless another use says `u32` or a written operand does not fit an `i32`. The compiler must solve all values of the module together, so that the result does not depend on source order. Resolve the local, callee and receiver by their declarations, including through nested scopes and inherited members; an override supplies its own signature. Uses that require `i32` and `u32` must be refused with the annotation remedy, and an integer use beside a float use must be refused where the float use stands. Where no use decides, the value must be an `f32`: that is the compiler's choice, and no default type is part of the language. A `/` or a `/=` is an integer division only when one operand has an integer type the author wrote; where every operand is an integer by inference, it must be refused with the two edits that say which division is meant. The counter of a counted `for` keeps the type Rule 7.5 gives it, and the counter of a `for` that is not counted is such a `let`. An unannotated `const` whose initializer is written numbers, and `+`, `-`, `*` and `/` over written numbers and such constants, must be a constant of no fixed type: at module scope, in a function, or as a static field that no code writes. Its value is the ECMAScript value of the initializer. Each read of it must take the type that the written number would take in the same place, and a conversion (`u32(K)`) must convert the written number. A read that takes `f32` names the emitted `f32` declaration, and a read of another type writes the value. A `/` whose operands are all written numbers and constants of no fixed type must be refused where another read makes one of those constants an integer, a conversion to `i32` or `u32` included, with the two edits that say which division is meant.

- Rationale: this is WGSL's abstract-integer rule, read from every place a number reaches, so that an author writes a number as a number (`docs/owner-decisions.md` OD-7). The `f32` where nothing decides is the type such a value always had on this surface, so no program that compiled computes another value.
- Derives from: [Abstract Numeric Types](https://gpuweb.github.io/gpuweb/wgsl/#abstract-types) and [Conversion Rank](https://gpuweb.github.io/gpuweb/wgsl/#conversion-rank); surface §13.
