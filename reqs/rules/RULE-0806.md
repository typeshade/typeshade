**Rule 8.6.** An entry point must not be called from another function, and neither may a kernel function (Rule 8.22).

- Rationale: WGSL forbids it, and an entry's parameters are stage inputs no caller can supply.
  A kernel function's arrays are the call's storage, which no shader function can hand over, and its loops are dispatches the host makes.
- Derives from: [Restrictions on Functions](https://gpuweb.github.io/gpuweb/wgsl/#function-restriction) ("an entry point must never be the target of a function call").
- Enforced by: `TS8099` (`"fs" is a fragment entry point and cannot be called; the pipeline invokes it. Move the body into a plain function and call that from both.`), pinned by `src/compiler/ts/operators-statements.test.ts` (`refuses calling an entry point`) (#160); for a kernel function `TS8099` (`"total" is a kernel function, which host code calls and whose arrays are the call's storage, so no function can call it. …`), pinned by `src/compiler/ts/kernel-loops.test.ts` in the compiler and the language service.
