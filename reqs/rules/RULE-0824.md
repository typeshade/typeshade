**Rule 8.24.** An exported `@compute` entry is called from host code as `entry(bindings, workgroups)`.
`bindings` has one property for each binding the entry reaches through its calls, and no other, each the binding's host value (Rule 8.21); `workgroups` is the workgroup count, `n` or `[x, y?, z?]`, dispatched as written with no bound added, or `{ indirect, offset? }` (change 0075), the three counts x, y and z at element `offset` (a whole number, 0 when left out) of a `Resident<Uint32Array>` that an earlier call may have written, read when the call runs and not when it is made (Rule 11.8); the call returns a promise, and when it resolves every storage binding the entry wrote has been read back into the caller's value in place, or stays on the device in the `Resident` passed for it (Rule 11.8). In the body of a `fuse` scope (Rule 11.13) the call is recorded and forms a group of its own in the scope's plan, with the bindings Rule 11.13 gives it.
The host view types `workgroups` as `number | readonly [number, number?, number?] | { readonly indirect: Resident<Uint32Array>; readonly offset?: number }` in both of the entry's signatures. The call refuses an indirect count before anything runs, with a `TypeError` that names the entry and `workgroups.indirect` or `workgroups.offset`: an `indirect` that is not a `Resident` whose host value is a `Uint32Array`, an offset that is not a whole number from 0, an offset whose three counts run past the array (the message gives both numbers), a `Resident` of another owner (Rule 11.8), a scratch array of a `fuse` scope (Rule 11.13), a destroyed `Resident`, and an array that is also a binding the entry writes or binds `read_write`, since WebGPU refuses a buffer that one dispatch reads its counts from and writes; an array the entry only reads may be a binding of the same call. An object with another key, or with no `indirect`, is refused as a wrong count is.
It runs on WebGPU where there is a device, the device of the runtime `configure({ runtime })` names or else the one the call layer requests and the default program runtime shares (Rule 11.11), then on WebGL2 as the pass program of change 0054 (Rule 11.8), and otherwise on the CPU tier, in the order `configure` sets (Rule 11.8), every invocation of every workgroup in turn, `z`, then `y`, then `x`, with the workgroup memory zeroed for each workgroup; an entry that reaches a barrier needs a GPU tier, WebGPU or WebGL2, and where there is neither the call is refused with a `TypeError` naming the barrier and its line.
In `vite dev`, and in a production build whose plugin says `console: 'always'`, an entry's WGSL records its `console.*` calls (Rule 11.9), and the runtime prints the decoded events to the host's console after the dispatch or the draw, in the CPU tier's order; `console: 'never'` records in neither, and the default, `'dev'`, records in `vite dev` alone. Each printed line, from the GPU or the CPU tier, starts with its tier, the call's file and line, and the invocation when the event has one, in the format string, with the event's arguments after it and its method kept.
An exported `@fragment` entry that reads no builtin but `position` and `front_facing` and writes one `@location(0)` `vec4` (its result, or a struct of that one field) is drawn as `entry(target, bindings)`: one frame, with a full-screen triangle, into `target`, an `HTMLCanvasElement` or an `OffscreenCanvas`, filling its width by height; the draw returns a promise that resolves when the frame is submitted, and reads nothing back.
It draws on WebGPU, then WebGL2 (the entry's GLSL ES 3.00 fragment program, its rows copied so the first is the canvas's top, as WGSL's `position` counts them), then the CPU tier, pixel by pixel; the first draw into a canvas decides its tier, since a canvas keeps the first kind of context it hands out, and every later draw into it uses that tier; the frame is opaque on every tier.
An entry the CPU tier cannot run (one that reaches a texture, or a call only a GPU computes) needs a GPU tier, and where it has none the call or the draw is refused with a `TypeError` naming why.
An entry that reaches a binding with no host value (a storage texture, a depth texture, a texture of another dimension, an emulated `f64`), a fragment entry that reads what a vertex entry writes, and a vertex entry stay `never` in the host view, naming the work that adds it.

An imported compute entry also takes the optional third argument `{ constants }` (change 0084), with the names, types, range checks and normalized values of `program.compute` (Rule 11.11). Omitted values keep their authored defaults. The selected values resolve the workgroup shape and workgroup-array lengths; the supplied workgroup count, including an indirect count, stays as written.

- Rationale: an entry is the escape hatch below the loop that becomes a kernel (change 0013), and it runs as its author wrote it: WGSL's unit, the author's own bound check, no guard added.
  The call replaces what a host otherwise writes by hand around `compile()` and `reflect()`: the device, the module, the layouts, the packing, the dispatch and the readback.
  The workgroup memory and the order of invocations on the CPU tier are those of the interpreter's own dispatch, so the two agree; a barrier needs the interpreter's generators to run in lockstep, which the runtime does not ship.
  An indirect count lets a kernel decide the size of the next call, so a host submits a chain of calls with no read between them (change 0075): WebGPU's `dispatchWorkgroupsIndirect` reads the three counts from a buffer. The offset counts elements, so its byte offset, four times it, is always the multiple of 4 that WebGPU requires.
  A fragment entry that reads only its pixel's position needs no vertex data, so one triangle the runtime supplies draws it on every tier; one that reads interstage values needs a mesh, a vertex count and a topology, which is #204's rendering design.
  GLSL's `gl_FragCoord` counts rows from the bottom and WGSL's `position` from the top, so the WebGL2 tier draws into a framebuffer and copies it upside down, and one program gives one picture on both.
