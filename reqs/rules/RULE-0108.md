**Rule 1.8.** A construct of the language is written in the language's own syntax: the directive, a type of the surface, or an attribute `@name` or `@name(…)` on the declaration it marks.
A construct that marks a function, its stage or its dispatch is an attribute `@name` or `@name(…)` on the function's declaration.
A construct that describes a value that flows into or out of an entry (an entry's parameter, a field of an entry I/O struct, an entry's result) or a binding is part of its type.
A parameter qualifier, which states that a function writes back to its caller's variable, is an attribute `@inout` or `@out` written before the parameter it marks (Rule 8.25).
A construct must not be written as a call of a function whose only role is to carry it.
A construct exists only for what the author must state and the compiler cannot know or prove; an optimization the compiler can prove exact, a tuning parameter and a validation the compiler can satisfy by rewriting the program are the compiler's work.
Where the compiler chooses a tuning parameter by default, an attribute may let the author state it explicitly, as `@workgroup_size([n])` does for a kernel (Rule 8.22): the default is the compiler's choice, and the attribute is an override, never a requirement.
TypeShade borrows TypeScript's syntax and is not TypeScript: whether a TypeScript tool (`tsc`, a formatter, a linter, a bundler) accepts a form is not a criterion for the surface, and the tooling for the language's own syntax is the project's work, as it is for Vue single-file components and JSX.

- Rationale: a `"use typeshade"` file is a program in the TypeShade language, and its own compiler and language service read it (Rule 3.1). A call of a fixed function name presents a construct as a library API. Change 0111 D1 measured the surface against a plain `tsc` and replaced `@vertex` with `vertex(f)`; later revisions of change 0130 measured it against prettier, typescript-eslint, esbuild and Bun and proposed to infer the stage. The owner rejected both criteria on 2026-11-09. The owner decided on 2026-11-09 that a parameter qualifier is written before the parameter, as GLSL writes `inout float a`, and that an entry's I/O stays in the type (`docs/owner-decisions.md`, OD-5). Rule 1.4 still holds where an ECMAScript form carries the meaning; a call whose only role is to mark its argument does not carry it. Rule 1.7 holds: the language service keeps an attribute as a form TypeScript parses, drops TypeScript's grammar report on it, and checks its content with the compiler's own check of that form. `docs/roadmap.md`'s first rule, "ordinary TypeScript first", reads as: borrow TypeScript's spelling for what TypeScript can say, and write the rest in the language's own syntax.
