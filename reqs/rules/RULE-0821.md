**Rule 8.21.** A host call passes and returns host values by value: an `f32`, `f64`, `i32` or `u32` is a `number`, a `bool` a `boolean`, a vector a tuple of its components, `readonly` in the host view as an argument and as a result (change 0116, decision D1), a matrix a flat column-major array of its components, an `array<T, N>` an array of `N` host values of `T`, a struct an object of its fields, an instance of its exported class among them (change 0109), an `enum` member its number, and a value of a key type (Rule 4.1), as a parameter or a result, one of its members as a string, which the call refuses when it is none of them, and a `Record` over a key type, as a parameter or a result, an object with one property for each member, which the call refuses when one is missing or another is there (change 0081); in a binding and in an array with no size, a key is its id, a number, and a `Record` the array of its values in id order.
The host view spells each host value with the name the shader writes, from the host type family that `typeshade/runtime` exports as types (change 0116): `f32`, `f64`, `i32` and `u32` are each a `number`, and `bool` a `boolean`, with the name as an optional phantom property, so that a plain literal is a value of each and no name is another; a vector is a `readonly` tuple of its scalar (`vec3`, `vec3u`), and a matrix a `readonly` tuple of its components, column-major, with its name as a scalar has its name (`mat4x4`, `mat4x4<f64>`, decision D9); `array<T, N>` is a `readonly T[]`; and an array with no size, which a kernel function and an entry's binding take, is `array<T>`, its typed array or its array of objects below, and for a scalar or a vector `T` a `Buffer` of it, and for a vector also a `Buffer` of its scalar (Rule 11.8, decision D3; change 0138, Amendments A10, Q-I, and A11, Q5). A struct is spelled with the name the view declares for it, as an argument and as a result (decision D7): the object of its fields for an `interface` or a `type`, and the class for an exported class, whose instance a host builds with `new`, while the call still takes a plain object of the fields; a struct is spelled by its fields where the view declares no name for it, in a result of an abstract class's struct, which is an object of its fields, in a constant, which is a frozen object of its fields, and in a binding and an array with no size where it holds a key or a `Record`, which they hold as ids; a binding of a struct type in the manifest's `Pack` is the struct's name, where the view declares one, beside the packed forms the runtime takes (decision D8). An enum, a key type and a `Record` keep the spelling the view gives them. The view imports the names it writes from the runtime it imports `Pack` from, and the family has one name for each value type the ambient library declares, and no other (Rule 12.7).
Null-only and three-state optionals, nullable classes and nested nullable fields also have no host representation (change 0098); optional storage cannot cross a host or entry boundary.
A struct is checked by the fields it declares, wherever its object is taken (a parameter, a field, an element of an `array<T, N>`, an element of a kernel function's array or a binding of an entry), and the check ignores the prototype; a struct a result holds is an instance of its class when the module exports the class as a value and the class is not abstract (Rule 8.20, change 0109, decision D1), with the fields its own properties and its constructor not run, and a plain object of its fields otherwise. A method of an instance takes and returns host values as a helper call does, and one that changes its object (Rule 8.10) writes the instance's fields back in place.
A fieldless class is `{}` on the host and CPU. Its reflected memory footprint accounts for the
GPU's internal carrier: four bytes under natural layout, sixteen under std140, with no visible
fields. Nested fields and array strides follow that footprint.
Each argument is checked and converted: an `ArrayLike` of the right length becomes a fresh array, an `f32` is rounded as a buffer write rounds it, and a value that does not fit is refused with a `TypeError` naming the function, the parameter and its TypeShade type; the result aliases no argument and nothing the module keeps (Rule 8.8), and an exported constant is a frozen copy.
A call of a function this rule and Rule 8.20 admit is synchronous, and no later tier changes that; as a helper's parameter, a runtime-sized array, an atomic, a texture, a sampler and a binding have no host value, and neither has an optional value (`T | undefined`, Rule 7.10), a struct with an optional field, an array of optionals or an optional parameter `x?: T`, as a parameter or as a result (change 0088, decision D4; change 0093, decision D7), the reason naming the parameter or the field (`field R.w: an optional value, f32 | undefined, has no host value yet (Rule 8.21)`): a host mapping such as `number | undefined` needs a later proposal.
A binding of an entry a host calls (Rule 8.24) takes a host value too: a `uniform<T>` or a sized `storage<T>` takes `T`'s, a runtime-sized `storage<array<T>>` of scalars or vectors takes the scalar's typed array (`Float32Array`, `Int32Array`, `Uint32Array`, or `Float64Array` for an `f64` and a `vecNf64`) with the vector's components one after another, which the call pads to the element's stride, one of structs takes an array of objects, one of scalars or vectors may be a `Buffer` of the scalars (Rule 11.8; change 0138, Amendment A10, Q-I), an atomic takes its integer's, a `texture_2d<f32>` takes an image source (`ImageBitmap`, `ImageData`, `HTMLImageElement`, `HTMLCanvasElement`, `HTMLVideoElement` or `OffscreenCanvas`), uploaded at the call, and a `sampler` takes `{ filter?, address? }` (`'nearest'` or `'linear'`; `'clamp'`, `'repeat'` or `'mirror'`), or nothing for linear and clamp. A `uniform<T>` of a class the module exports also takes a `Uniform<T>`, and a `storage<array<T>>` of one a `Buffer<T>`, an exported binding among them (below). An emulated `f64` (change 0013's split) is held by the GPU as two `f32`s, `hi` and `lo`, and a `vecNf64` as a plane of each: the runtime splits a double into them and joins them back, and binds the `_fp64` guard of a module that emulates one, which the host never passes; a `matNxN<f64>` has no host value yet.
A storage binding the entry writes is read back into the caller's value in place, so a written binding whose type is one scalar is passed as a typed array of length one. A `Buffer` the entry writes is not read back: its values stay on the device until its `read()` (below).
A buffer binding of a program runtime's draw or dispatch (Rule 11.11) takes the same host value, for a storage array with no size of scalars or vectors also a `Buffer` of the scalars, or the host's own buffer, and the host view types the module's default export, its manifest, with the bindings each entry reaches and those values (change 0030). A geometry's vertices take a `Buffer<f32>`, `Buffer<i32>` or `Buffer<u32>`, and its indices a `Buffer<u32>` (change 0138, Amendment A11, Q3).
A kernel function (Rule 8.22) called with plain data is asynchronous: it returns `Promise<void>`, or `Promise<R>` for a result `R`; its value parameters take the host values above, its arrays with no size take the scalar's typed array (`Float32Array`, `Int32Array`, `Uint32Array`, a vector's components one after another) or, for a struct, an array of objects, and each array it writes is read back into the caller's in place. Called on a resource (below), it has a second signature, which takes a `Buffer` of the scalars for an array with no size of scalars or vectors, a `Buffer<C>` for one of an exported class `C`, a `Uniform<C>` for a parameter of type `C`, and a `Buffer` of one element for a number or a vector parameter, and which returns nothing, or for a result the result's `Buffer`s (below); and a third, for a call on a resource that writes a plain array, which returns a promise of its result as plain data (below). An array a loop pushes onto may come with its length, `{ array, length, offset? }`, the array and the element `offset` (a whole number, 0 when left out) of a `Buffer<u32>` that holds its length (Rule 8.23, change 0094; change 0138, Amendment A10, confirmation item 3), which the host view offers on such an array only (decision D5), and a call with one is a call on a resource; before anything runs, the call checks each array against the indices a loop writes at `a*i + c` and refuses one too short with a `TypeError` naming the function, the parameter and both numbers, except for a loop whose range the device holds (Rule 8.22, change 0094), whose trip count the host does not know before the loop runs: a write such a loop makes past an array's end is dropped on every tier (decision D2).
The call validates every declared object field even when its private GPU input omits an unused field (change 0082). Projection changes no host type or refusal.
A resource is a host value too (change 0138, R7 to R9 and R17): `uniform(C, init?)` from `typeshade/runtime` makes a `Uniform<C>` of a class `C` a shader module exports, laid out by the uniform rules of Rule 6.8, `zeros(C, n)` and `array(C, data)` make a `Buffer<C>` of `n` elements laid out as a storage array with no size, and an exported resource is one of them (Rule 6.1). `array(xs)` of a `Float32Array`, an `Int32Array`, a `Uint32Array` or a `Float64Array` makes a `Buffer` of its scalars, a `Buffer<f32>`, `Buffer<i32>`, `Buffer<u32>` or `Buffer<f64>`, `array(xs)` of a `number[]` a `Buffer<f32>` of its numbers as a `Float32Array` holds them (the owner's decision of 2026-11-11), and `array(length, element)` a zeroed one of `'f32'`, `'i32'` or `'u32'` (change 0138, Amendment A10, Q-I); `array()` refuses, with a `TypeError`, a value that is no array, which the host keeps as `uniform(C, init)` or passes as plain data, and an array that holds anything but numbers, which is `array(C, data)` for structs or plain data (Amendment A11, Q3 and Q4). A `Buffer` of scalars holds a typed array of its own, which takes no range of the region (Amendment A11, open item on R17), and has the members of every `Buffer` (A11, Q1): `length`, which counts elements, a vector being one (A11, Q5); `set(data)` of numbers; `resize(n)`; `at(i)`, element `i`'s view, whose `get` gives a number, or for a vector a typed array of its components, and whose `set` writes one; `needsUpdate`; `dispose()`; and `read()`, which gives the typed array of its scalar, a vector's components one after another (A11, Q2 and Q5). Each is a byte range of one memory region, an `ArrayBuffer` that is resizable where the runtime has one, with an accessor for each field over a typed view of the region, made again after the region moves its ranges. `set` checks each number as a call checks it, writes only a changed number, marks its bytes dirty and allocates nothing: a uniform widens its one dirty byte range, and a buffer keeps a dirty range for each element written, joins two ranges that touch, and joins all its ranges into one when it holds more than 16 (change 0138, Amendment A5, D2); `get` returns a scalar field's number, for an `f64` the number of its two halves, and the view of a vector, a matrix or an array field, `Readonly` (Amendment A5, D1); `needsUpdate = true` marks a write through a view; `buffer.at(i)` is element `i`'s accessor, and `await buffer.read()` returns the elements as instances of the class. The host sets a buffer's length again (change 0138, Amendment A3): `buffer.resize(n)` gives it `n` elements, of which the ones that fit keep their values and a new one is zero, and `buffer.set(data)` gives it the length of `data` and its values, a field that `data` does not name being zero, and changes nothing when a value does not fit. Each gives the buffer another range of the region and marks the whole range dirty; an accessor made before reads the new range, and one of an element that is gone throws a `TypeError`. An exported `storage<array<T, N>>` keeps its `N` elements, so it refuses another length with a `TypeError`. A resource is freed by `dispose()`, by `using`, which calls its `[Symbol.dispose]()`, or when the garbage collector reclaims it, and an accessor of a freed one throws a `TypeError` that names it; the types of `Uniform` and `Buffer` declare `Disposable` where the host's `lib` declares `Symbol.dispose` (Amendment A5, D4). An exported resource lives as long as its module, so its type has no `dispose()` and no `[Symbol.dispose]()`, and its `dispose()` throws a `TypeError` (Rule 6.1, Amendment A5, D7). A kernel function and a `@compute` entry take a resource (change 0138, R2): a `Buffer<C>` for an array with no size of `C` or a `storage<array<C>>` binding, a `Buffer` of the scalars for one of scalars or vectors, a `Uniform<C>` for a parameter of type `C` or a `uniform<C>` binding, an exported resource among them, and a `Buffer<u32>` as a held length or an indirect workgroup count. A call that takes one does not block. It returns nothing, or for a kernel function's result `Buffer`s, made at the call on the call's device (Amendment A10, Q-C): a `Buffer` of one element for a number or a vector, a `Buffer` of `N` elements for an `array<T, N>` of them, and for a struct an object of them with the struct's own fields, a nested struct an object of its own (R1; Amendment A11, Q6); `read()` gives each one's values. A number or vector parameter takes a `Buffer` of one element of its scalar, and the call reads the element when it runs, so a result is another call's argument (A10, Q-C). It checks every argument at the call and records the call, and the runtime submits it later, in the order of calls (Rule 11.8). The call sees the values its arguments hold when it is made (Amendment A5, default 3): a `Uniform`'s value, and the dirty ranges of a `Buffer`, which the call copies out and marks clean. Those ranges are written to the device copy before the call runs. `await buffer.read()` submits the recorded calls, waits for those before it, and lands what they wrote in the buffer's range of the region (R17). The window of a `Buffer` is the time from a call that writes it to its `read()`; in it, the region does not hold what the device holds. In the window, `set` of that buffer throws a `TypeError` that says to await `read()` first, as `get` does (the owner's decision (a) of 2026-11-11). `set(data)`, `resize` and `needsUpdate` throw it too, which the owner accepted with the merge of the slice that added them (change 0138, Amendment A7). A `Buffer` of scalars has the same window: its element view's `get` and `set`, `set(data)`, `resize` and `needsUpdate` throw it from a call that writes it until `read()` (Amendment A11, Q1). Beside the checks of a call with plain data, a call on a resource refuses, with a `TypeError` at the call: a result no `Buffer` holds yet (a `bool`, a key, a matrix, a `Record`, an array of structs, and a struct that holds one), naming the function; a collection or a sized binding the call writes that is no `Buffer`; a `Buffer` of another class; a `Buffer` where no array with no size is taken, a sized storage binding among them; a `Buffer` for a parameter that is no number and no vector, or of more than one element there; and a `Buffer` of scalars of another element, or one whose length is no whole number of the vector's components (Amendment A11, Q5). Each refusal but the first names the function and the parameter or the binding, and a refused call changes no `Buffer`. A call on a resource that writes a plain array with no size waits: it returns a promise, fills the array in place when it has run, and gives its result as plain data (R2 as amended by Amendments A10 and A11, Q7). A call that takes no `Buffer` and no `Uniform` is the call this rule and Rule 11.8 give above. A recorded call that fails when it runs throws its error at the next `read()` or call, with the line of the failed call (Amendment A5, default 7). A `Buffer` that the failed call writes keeps the error: each later call that takes it, and its `read()`, throw it until `set(data)` or `resize()` gives it new values (the owner's decision (b) of 2026-11-11), a `Buffer` of scalars as a `Buffer` of structs (Amendment A10, Q-I). The failed call leaves the window, so `get` reads the region again: what it held before the writing calls not yet read back. The error is also thrown once at the next `read()` or call, wherever it is, a call with plain data and a draw among them. So after a recovery with `set(data)` or `resize()`, that next `read()` or call throws it, unless one threw it since the failure, and the call after it works. A draw takes no resource yet.

- Rationale: the representation is the one the CPU tier already runs on (`src/core/cpu-runtime.ts`), typed precisely in the host view, so there is nothing to construct and a wrong shape is a type error before it is a `TypeError`.
  The view spells each type with the name the source writes, so a host developer reads the signature the shader declares, and an `f32` and a `u32` stay two types (`docs/dx.md` principle 2, change 0116).
  The check at the call is for the caller `tsc` did not read: an IR node passed as a vector gave `NaN` in silence, and a `Float32Array` added to another gave a string.
  A later tier takes new shapes (an entry point, a runtime-sized array parameter) that are asynchronous from the day they appear, so a helper's call site never gains an `await` it does not need (`docs/dx.md` principle 4).
