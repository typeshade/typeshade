**Rule 1.6.** TypeShade code is compute code: it computes results from data, may run in parallel, and gives the same answer on every target.
Code that reaches the world outside the computation (input and output, the network, the DOM, timers, the clock, unseeded randomness, `eval`, a dynamic `import`) is host code, written in TypeScript as today.
A form TypeScript authors commonly write in compute code, a form of the language or a member of its standard library, must be supported by the compiler.
A TypeShade name or a library function is not a substitute for it; a library holds what TypeScript has no standard form for.
A refusal is the last resort, and names the reason the compiler cannot represent the form on that target (Rule 1.5).

- Rationale: a TypeShade author is a TypeScript developer. A form they reach for first and find refused costs them a detour, and the detour is code: TypeCV's audit of 2026-10-27 counts 188 lines of hand-made hash tables, 122 of sorting and 77 of bounded lists that a `Map`, `sort` and `push` would hold. The §9.3 table (Rule 9.6) is already shrink-only; a row whose TypeScript form the compiler comes to support is deleted by Rule 13.7. The boundary is the present stage's, not a permanent one, and a refusal of host code names the host as the place to write it.
