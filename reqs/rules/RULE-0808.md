**Rule 8.8.** An object has the identity a JavaScript object has (change 0142).
An object is a struct, an instance of a class, or an array, with a size or with none.
A function of the file or of a namespace changes the caller's object when it writes a field or an element of its object parameter, calls `push` or `fill` on it, calls on it a method that writes its object (Rule 8.10), or hands it to a parameter that its function writes.
The author writes no qualifier: the compiler reads the source and passes the caller's place (Rule 8.25).
A number, a `bool`, a vector and a matrix are values, as a JavaScript primitive is.
A function gives a value back by returning it, and a list assignment, `[a, b] = f(a, b)`, takes two results apart.
An author writes no pointer value: no `ptr`, no `&` and no qualifier.
Whole-value assignment, compound assignment and integer updates of a value parameter must
rebind a mutable local initialized from the input, leaving the caller's value unchanged.
A whole assignment to an object parameter (`p = new P()`) makes `p` name a local, and the caller's object does not change. Where the body writes the caller's object through `p` before that assignment, the assignment is `TS8099`, not supported yet (change 0142, stage 2): the compiler does not yet keep the caller's object and the local apart under one name. A loop name, `for (let p of ps)`, follows the same rule.
Only a parameter whose declaration a whole write resolves to gets this local; a shadowing
declaration does not count. Within that body's scope the local may be written through its
fields or elements. A value parameter with no whole write retains its existing read-only place
semantics. Resource handles and the reference-backed arrays of Rule 8.23 are not local-copy values.
`const q = p`, `let q = p`, `for (const q of ps)` and `let b = f(a)`, where `f` returns its parameter, name the object a second time when something writes the object through a name: `q` is a second name, and the declaration emits nothing.
A statement that stores an object another name holds (`q = a`, `xs[0] = a`, `[a, a]`, `new B(a)`, `const q = xs[0]`) is a copy where nothing writes the object afterwards, and a copy has the result JavaScript gives.
Where something does write it afterwards, the statement is `TS8099`, "One object under two names is not supported yet (change 0142, stage N)", and is never compiled to a copy that JavaScript would not make (OD-9).
A copy is written with a name JavaScript has, and the language adds no copy construct (change 0142, Table 3): `xs.slice()` of numbers or vectors, and `structuredClone(v)` of a struct that is no class or of an array with a size.
`[...xs]` alone is `TS8013`, and its sentence names `xs.slice()`; `structuredClone` of an instance of a class and `slice()` of an array of objects are `TS8099`, not supported yet (stage 3).
`f(a, a)` where `f` writes one of the two, a module variable passed to a function that also uses its name (`TS8074`), and `===` or `!==` between objects (`TS8003`) are refused as not supported yet (change 0142, stage 2).
A parameter of a method, a constructor, a setter, a local function, a function handed as an argument and a generic function takes a value in this version, and a write to an object one is `TS8018` until stage 2 of change 0142.
An entry's parameter is the pipeline's value, which no caller in the program holds. A write to a field or an element of it is `TS8018` in this version, not supported yet: copy the value into a `let` and write that.
The object of a method that changes its object, and a variable of the function around it that a local function writes, are not parameters an author writes: Rules 8.10 and 8.17 govern them, and each is passed by reference.
A kernel function's parameter of an array with no size is the caller's storage (Rule 8.23).

- Rationale: a struct, an instance of a class and an array are objects in JavaScript, and a function that writes its parameter changes the caller's object there. The compiler reads which parameters a function writes, so the author writes no mark for it (OD-3, OD-5). A number is a value in JavaScript, so a function that changes one returns it.
  The contract is about identity and sharing only: which object a name refers to, and who sees a write to it, is never other than what JavaScript says. Where the compiler does not implement a form yet, it refuses the form with a text that says so (OD-9).
  The two references of Rules 8.10 and 8.17 are how the emitted function keeps TypeScript's own meaning (a method writes the object it was called on, a closure writes the variable it closes over), and no author writes either one.
