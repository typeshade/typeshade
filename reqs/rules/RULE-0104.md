**Rule 1.4.** Where ECMAScript has a form that carries the GPU meaning, the surface must borrow TypeScript's spelling; a WGSL spelling is borrowed only where no ECMAScript spelling carries the meaning, and the borrowing must keep every WGSL capability reachable (Rule 11.14).
A form may be borrowed in part: the members, the positions or the meaning it takes are those the rules give it.
A WGSL capability that only switches off a validation the compiler satisfies by rewriting the program is not borrowed: the compiler's rewrite gives the program the capability would have admitted. The `derivative_uniformity` filter is such a capability (Rule 8.5). Its rows in `docs/capability-coverage.md` are `refused` with this rule (Rule 11.14, Rule 11.18).

- Rationale: the WGSL vocabulary is there to say what TypeScript cannot say, such as a value's width or an address space. It is not a second spelling an author has to learn for what TypeScript already says. A filter that switches a validation off is not something the author must state: it asks the author to learn a WGSL rule name and its severities for work the compiler can do, and the program it leaves is indeterminate in WGSL and undefined in GLSL ES 3.00. The language keeps a construct only for what the author must state and the compiler cannot know (`docs/owner-decisions.md`, OD-3).
