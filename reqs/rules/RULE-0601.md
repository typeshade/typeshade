**Rule 6.1.** A resource must be written `declare const x: uniform<T>`, `declare const x: storage<T>`, `declare const x: storage<T, "read_write">`, or `declare const x: <texture or sampler type>`.
It must have no initializer, and its binding slot is the source order of `declare` in the file.
A resource is never declared with `let`: `declare let x: storage<T>` and `declare let x: uniform<T>` are both refused, and each refusal names the `declare const` form of the line it is on.
A resource may be exported, `export declare const x: uniform<T>`, and an exported resource is a host resource (change 0138, R10): a shader file that imports it reads the same binding (Rule 3.9), and a host file that imports it receives a value of `typeshade/runtime` (Rule 8.21). A `uniform<T>` of a class the module exports is a `Uniform<T>`, and a `storage<array<T, N>>` of such a class is a `Buffer<T>` of `N` elements; the generated module makes each one once, and the host sets its fields with `set` and reads them with `get`, never with `=`, since an import is a read-only binding. A `storage<array<T>>` of such a class, which states no size, is a `Buffer<T>` whose length the host sets (change 0138, Amendment A3): `resize(n)` gives it `n` elements, and `set(data)` the length of `data` and its values (Rule 8.21). The shader file does not state the size. Until the host sets the length, `length` is 0, and `at` and `read` throw a `TypeError` that names the binding and says to call `resize` or `set`. Any other exported resource (a scalar, a vector, a struct no exported class declares, an array of scalars or vectors, one `storage<T>`, a texture, a sampler) is `never` in the host view, with the reason. An entry call still takes the resource's value in its bindings object (Rule 8.24).
The host reaches each field of a host resource as a property of its accessor, so a field named like a member of that accessor is refused (`TS8079`, change 0138, Amendment A5, D3, and Amendment A6). The names are `set`, at any depth of the class of an exported `uniform<T>` or of the element of an exported storage array, and `needsUpdate` and `dispose` on the class of an exported `uniform<T>` itself. Only an exported resource that is a host resource is read: its class is a class the module exports, is not abstract and has the layout of its address space. The refusal stands on the field's declaration, in the class that declares it (a class above for an inherited field), once for each field, and names the binding by the name the module exports it as. The compiler and the editor report it with the same code and text. A class that no host resource holds may have such a field. A host that passes such a class to `uniform()`, `zeros()` or `array()` of `typeshade/runtime` gets a `TypeError` from the runtime, and its editor reports `TS2345` (`TS2769` for `array()`), whose text names `TS8079` and the field (Amendment A6). An exported resource lives as long as its module, so its type in the host view is the `Uniform<T>` or the `Buffer<T>` without `dispose()` and `[Symbol.dispose]()` (Amendment A5, D7), and it is not assignable to a parameter of type `Uniform<T>` or `Buffer<T>`.

- Rationale: `declare` is TypeScript's own word for a value that exists elsewhere, which is what a host-owned resource is, and `const` is the only keyword that says anything true about one, since nothing rebinds the name.
- Derives from: [Variable and Value Declarations](https://gpuweb.github.io/gpuweb/wgsl/#var-and-value), [Address Spaces](https://gpuweb.github.io/gpuweb/wgsl/#address-space), [Shader Interface](https://gpuweb.github.io/gpuweb/wgsl/#shader-interface); surface §1, §7 and §15.
