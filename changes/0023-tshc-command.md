## What changes

The compiler's command is named after the package today: `package.json` maps the `bin` name
`typeshade` to `src/cli/bin.ts`, and its two commands are `typeshade check` and
`typeshade sync`. After this change the command is `tshc`, for TypeShade compiler:

```sh
tshc check src/       # was: typeshade check src/
tshc sync             # was: typeshade sync
tshc sync --check     # was: typeshade sync --check
```

The package stays `typeshade` and installs the command, as the `typescript` package installs
`tsc`. What the command prints moves with its name:

| What                            | Before                                                                                          | After                                                                                      |
| ------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| the `bin` entry                 | `typeshade`                                                                                     | `tshc`                                                                                     |
| the usage text                  | `Usage: typeshade check [options] [paths...]`                                                   | `Usage: tshc check [options] [paths...]`                                                   |
| the prefix of an error          | `typeshade: unknown command "build".`                                                           | `tshc: unknown command "build".`                                                           |
| `sync --check` on a stale view  | `src/terrain.shade.typeshade.ts is stale; run typeshade sync.`                                  | `src/terrain.shade.typeshade.ts is stale; run tshc sync.`                                  |
| the host view's first line      | ``// Generated by typeshade from terrain.shade.ts. Do not edit; `typeshade sync` rewrites it.`` | ``// Generated by typeshade from terrain.shade.ts. Do not edit; `tshc sync` rewrites it.`` |
| this repository's script for it | `bun run typeshade check src/`                                                                  | `bun run tshc check src/`                                                                  |

Everything else that says `typeshade` names the package or the language, not the command, and
stays:

- the package (`npm install typeshade`) and every import specifier: `typeshade`,
  `typeshade/vite`, `typeshade/runtime`, `typeshade/language-service` and the rest;
- the directive `"use typeshade"`, the host view's name `name.shade.typeshade.ts`, and
  `moduleSuffixes: [".typeshade", ""]`;
- the Vite plugin, `typeshade()`, and "Generated by typeshade" on the view's first line, since the
  plugin writes the same view;
- a diagnostic's `source`, `"typeshade"` or `"typescript"` (`CheckDiagnostic`, the language
  service), which names the half that raised it, as an editor labels TypeScript's own
  diagnostics `ts` and not `tsc`.

What the two commands do, their options, their output and their exit statuses do not change.

## Why

The maintainer named the command `tshc` on 2026-09-28. A compiler's command usually has a short
name of its own, like `tsc`, `gcc` and `nvcc`, and the `typescript` package installs `tsc`.
Today one word, `typeshade`, is the package, the directive, the language and the command, so a
sentence that says `typeshade` can mean any of them.

**The name is free.** Measured on 2026-09-28: npm has no package named `tshc`, and none of the
packages its search returns for the name installs a command of that name; command-not-found.com
knows no package of a Linux distribution or of Homebrew that installs one, and Homebrew has no
formula of that name; PyPI and crates.io have no project of that name. So wherever `typeshade` is installed, `tshc` is its command. Where it is not,
`npx tshc` stops with npm's `E404` (measured with `CI=true`, in a project without the package)
rather than installing another package and running its command. The documents write
`npx -p typeshade tshc check src/` (in Bun, `bunx -p typeshade tshc check src/`) for a run that
may not have the package installed. A `package.json` script, such as surface §64's
`"prepare": "tshc sync"`, runs with `node_modules/.bin` first on its `PATH` and never installs
anything.

The names it was chosen over:

1. **`tscc`, the first name.** Eight npm packages install a command named `tscc`, among them
   `tscc` 0.0.2 (2013, a wrapper around `tsc`) and `@tscc/tscc` 0.9.4 (2022, bundling through
   Closure Compiler, 92 downloads in the last week). `npx tscc` runs this package's command only
   where `typeshade` is installed. Anywhere else it installs the package named `tscc` and runs
   that one, and in CI it does so without asking: npm's documentation of `npm exec` says "When
   standard input is not a TTY or a CI environment is detected, `--yes` is assumed". In a
   project that also depends on `@tscc/tscc`, npm 10.9.7 and Bun 1.3.11 both linked `.bin/tscc`
   to that package, in either install order, without a warning (measured with two local
   packages of those names).
2. **A three-letter name, like `gcc` or `tcc`.** Each one measured is taken. `tcc` is the Tiny C
   Compiler, and `scc` a line counter, in Linux distributions and in Homebrew; `hcc`, `sdc` and
   `tdc` are other programs' commands in Linux distributions (command-not-found.com). `ycc` is a
   compiler on crates.io and a command on PyPI. `tsc`, `tsx`, `tsd`, `tsp`, `tss`, `tsl`, `twc` and `tyc` are commands of npm packages.
   The least taken, `tgc`, is a command of two small npm packages, and its npm name belongs to a
   package that installs none.
3. **Keep `typeshade`.** No package clashes with it, and `npx typeshade check src/` works with
   nothing installed. It leaves the command without a name of its own.
4. **Ship `tshc` and keep `typeshade` beside it as a second name.** No published release has a
   command: npm holds `typeshade@0.0.0`, a placeholder with no `bin`, and `0.1.0` will be the
   first release (`CHANGELOG.md`). No script anywhere runs `typeshade` from a published package,
   so a second name would protect no one. Rule 13.10's window is counted in published releases,
   and before `1.0.0` it covers a change of meaning, not a spelling. A second name would also
   stay in every document that has to pick one.

## What it touches

- **Rule 3.8.** Its Enforced-by names `typeshade sync`, which writes a view for a `*.shade.ts`
  only. It becomes `tshc sync`.
- **Rule 3.9.** Its Enforced-by names `typeshade check` among the paths `linkProgram` serves. It
  becomes `tshc check`.
- **Rule 12.7.** "a program the compiler accepts must draw no error in the editor or in
  `typeshade check`" becomes `tshc check`. What the rule requires does not move, but its text
  does, so Doorstop marks the rule and the surface sections that explain it for review
  (`reqs/README.md`).
- **Rule 13.10.** The deprecation option on the command line, `typeshade check --deprecations`,
  becomes `tshc check --deprecations`.
- **Surface §64.** The setup's `"prepare": "typeshade sync"`, the first line of the host view it
  shows, and the paragraph on a clean checkout (`typeshade sync` writes every view first;
  `typeshade sync --check` fails on one that is missing or stale).
- **Surface §68.** "How each path reads the files": `typeshade sync` reads the imports from
  disk, and `typeshade check` checks a shader module a checked file imports.
- **Exports, codes and examples: none.** `checkDocuments`, `checkOpenDocument` and
  `CheckDiagnostic` keep their shapes, `source` included. No diagnostic names the command. The
  set of examples does not change; the comments of `examples/imported-noise.shade.ts` and
  `examples/_shade.ts` name `typeshade sync` and follow, and the emit goldens show that no
  emitted byte moved.

The code:

- `package.json`: the `bin` key `typeshade` becomes `tshc`, and so does the script of that name.
  `scripts/publish-manifest.ts` derives the tarball's `bin` from the same map and does not
  change. `src/cli/bin.ts` still finds its version by the manifest's `name`, which stays
  `typeshade`.
- `src/cli/run.ts`: `USAGE`, the prefix of each error, and `sync --check`'s remedy.
- `src/compiler/ts/host-face.ts`: the view's first line.
- The comments that name the command, in `src/cli/`, `src/language-service/`,
  `src/compiler/ts/`, `src/vite.ts`, `scripts/user-journey.ts` and `journeys/`.

The prose that names the command, which `bun run docs:impact` lists for the implementing pull
request: `README.md` ("Checking shaders from the command line", with the `npx -p` form, and the
host-import setup), `AUTHORING.md` ("The CPU oracle"), `AGENTS.md` (the `src/cli/` row),
`RELEASING.md`, `docs/dx.md`, `docs/use-typeshade-plan.md`, `docs/language-service-api.md` and
`journeys/README.md`; `reqs/` follows by `bun run reqs:sync`. `CHANGELOG.md` has nothing to
rename: the command was never published, and `[Unreleased]` does not name it. The proposals
that name `typeshade check` or `typeshade sync` (0007, 0009, 0010, 0016, 0017, 0022) record
what was decided then, and stay.

The tests that will pin it:

- `src/cli/run.test.ts`: the usage text and the prefix of each error read `tshc`, and the
  spawned `bin.ts` answers `--version` as before.
- `src/vite.test.ts`: `sync --check` reports a missing and a stale view with `run tshc sync.`
- `src/publish-manifest.test.ts`, D6: `package.json` declares one command, `tshc`, and the
  derived manifest maps it to the emitted `bin.js` under `dist/`.
- `bun run gate:journeys`: `journeys/_host-import`'s `prepare` runs `tshc sync` after a plain
  `npm install` of the packed tarball. That proves npm links the command under its new name,
  and that the views it writes are the ones `tsc` reads.

## What it owes downstream

- **typeshade.github.io.** No page of the site names the command at its pin (`9fbe5ef`):
  `typeshade check`, `typeshade sync` and `npx typeshade` appear nowhere outside `vendor/`. On
  the pin that carries this change:
  - the Korean translation of "The CPU oracle" (`content/guide/ko/the-cpu-oracle.md`) is
    translated again if `bun run check:guide` lists it, since the English names `tshc`;
  - the rule pages print the new text of Rules 3.8, 3.9, 12.7 and 13.10 from the pin, with
    nothing to edit: no page of the site records a fingerprint of any of the four
    (`READ_AGAINST` in `src/lib/design-rules.ts`, and `content/guide/ko/rules.json`);
  - any copy the site adds for the host-import setup or for CI writes `tshc`, and
    `npx -p typeshade tshc` where the package may not be installed.
- **vscode-typeshade.** Nothing there runs the command. These name it:
  - `packages/tsserver-plugin/src/fixtures.ts`: `HOST_IMPORT_PROJECT` reproduces the host view
    byte for byte, so its first line becomes `` `tshc sync` rewrites it ``, and its doc comment
    names `tshc sync`;
  - the skill's host setup, `plugins/typeshade/skills/typeshade/SKILL.md` and
    `references/host.md`, whose line becomes `"prepare": "tshc sync"`;
  - `docs/design.md`'s paragraph on the host view and `docs/agents.md` §3.1 (the `check` tool),
    where they name the command;
  - the comments of `packages/mcp-server/src/format.ts` and `tools.ts`.

## What comes next

- `tshc` keeps the two commands it has. A command that writes `.wgsl` and `.glsl` files, which a
  compiler's name may suggest, is not part of this change; if one comes, it is its own proposal.
- The name is free on npm today, and nothing keeps it so. A package named `tshc` that installs
  the same command would keep it, and would let `npx tshc` work with nothing installed. Whether
  to publish one is a release decision (`RELEASING.md`), outside this change.

## Decisions for the reviewer

Accepting this proposal accepts each of these. Each can be changed before acceptance without
touching the rest:

1. The command is `tshc`, over `tscc` and the three-letter names measured under Why.
2. `tshc` replaces `typeshade` as the command, with no second name, since no release has shipped
   one.
3. The package, the import specifiers, the directive, the host view's name, `moduleSuffixes`,
   the Vite plugin and a diagnostic's `source` keep `typeshade`.
4. The host view's first line keeps "Generated by typeshade", which the Vite plugin writes too,
   and names `tshc sync` as what rewrites it.
5. Only the name moves: `check` and `sync`, their options, their output and their exit statuses
   stay as they are.
