## What changes

The compiler's command is named after the package today: `package.json` maps the `bin` name
`typeshade` to `src/cli/bin.ts`, and its two commands are `typeshade check` and
`typeshade sync`. After this change the command is `tscc`:

```sh
tscc check src/       # was: typeshade check src/
tscc sync             # was: typeshade sync
tscc sync --check     # was: typeshade sync --check
```

The package stays `typeshade` and installs the command, as the `typescript` package installs
`tsc`. What the command prints moves with its name:

| What                            | Before                                                                                          | After                                                                                      |
| ------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| the `bin` entry                 | `typeshade`                                                                                     | `tscc`                                                                                     |
| the usage text                  | `Usage: typeshade check [options] [paths...]`                                                   | `Usage: tscc check [options] [paths...]`                                                   |
| the prefix of an error          | `typeshade: unknown command "build".`                                                           | `tscc: unknown command "build".`                                                           |
| `sync --check` on a stale view  | `src/terrain.shade.typeshade.ts is stale; run typeshade sync.`                                  | `src/terrain.shade.typeshade.ts is stale; run tscc sync.`                                  |
| the host view's first line      | ``// Generated by typeshade from terrain.shade.ts. Do not edit; `typeshade sync` rewrites it.`` | ``// Generated by typeshade from terrain.shade.ts. Do not edit; `tscc sync` rewrites it.`` |
| this repository's script for it | `bun run typeshade check src/`                                                                  | `bun run tscc check src/`                                                                  |

Everything else that says `typeshade` names the package or the language, not the command, and
stays:

- the package (`npm install typeshade`) and every import specifier: `typeshade`,
  `typeshade/vite`, `typeshade/runtime`, `typeshade/language-service` and the rest;
- the directive `"use typeshade"`, the host view's name `name.shade.typeshade.ts`, and
  `moduleSuffixes: [".typeshade", ""]`;
- the Vite plugin, `typeshade()`, and "Generated by typeshade" on the view's first line, since the
  plugin writes the same view;
- a diagnostic's `source`, `"typeshade"` or `"typescript"` (`CheckDiagnostic`, the language
  service), which names the half that raised it, as an editor labels TypeScript's own
  diagnostics `ts` and not `tsc`.

What the two commands do, their options, their output and their exit statuses do not change.

## Why

The maintainer named the compiler `tscc` on 2026-09-28. A compiler's command usually has a
short name of its own beside its package's (`typescript` installs `tsc`). Today one word,
`typeshade`, is the package, the directive, the language and the command, so a sentence that
says `typeshade` can mean any of them.

**The cost: two npm packages already install a command named `tscc`.** Measured on the registry
on 2026-09-28:

| Package      | Latest            | What it is                                                 | Downloads, last week |
| ------------ | ----------------- | ---------------------------------------------------------- | -------------------- |
| `tscc`       | 0.0.2, 2013-11-09 | a wrapper around `tsc`, depending on TypeScript `~0.9.1-1` | 18                   |
| `@tscc/tscc` | 0.9.4, 2022-10-20 | bundles TypeScript through tsickle and Closure Compiler    | 92                   |

Neither is this package, and two things follow:

1. **`npx tscc` runs this package's command only where `typeshade` is installed.** npx looks in
   the project's `node_modules/.bin` first. Where the command is not there, it installs the
   package named `tscc` and runs that one, and in CI it does so without asking: npm's own
   documentation of `npm exec` says "When standard input is not a TTY or a CI environment is
   detected, `--yes` is assumed". A run that may not have the package installed therefore names
   it: `npx -p typeshade tscc check src/` (in Bun, `bunx -p typeshade tscc check src/`). A
   `package.json` script, such as surface §64's `"prepare": "tscc sync"`, runs with
   `node_modules/.bin` first on its `PATH` and never installs anything, so the setup is safe as
   written.
2. **A project that also depends on `@tscc/tscc` (or `tscc`) runs that package's command.** Both
   declare the `bin` name `tscc`, and one `node_modules/.bin/tscc` can link only one of them.
   Measured with two local packages named `@tscc/tscc` and `typeshade`, installed together: npm
   10.9.7 and Bun 1.3.11 both linked `.bin/tscc` to `@tscc/tscc`, in either install order, and
   neither warned, so `npx tscc`, `bunx tscc` and a `prepare` script ran the other program. The
   weekly downloads above say this is rare; the troubleshooting line in `README.md` will name it.

The alternatives:

1. **Keep `typeshade`.** No npm package clashes with it, and `npx typeshade check src/` works
   with nothing installed. It leaves the command without a name of its own.
2. **Ship `tscc` and keep `typeshade` beside it as a second name.** No published release has a
   command: npm holds `typeshade@0.0.0`, a placeholder with no `bin`, and `0.1.0` will be the
   first release (`CHANGELOG.md`). No script anywhere runs `typeshade` from a published package,
   so a second name would protect no one. Rule 13.10's window is counted in published releases,
   and before `1.0.0` it covers a change of meaning, not a spelling. A second name would also
   stay in every document that has to pick one.
3. **A name no npm package installs.** `npx <name>` would then work with nothing installed, and
   no project could hold two commands of that name. The maintainer chose `tscc` with the cost
   above; decision 1 below is where to change the name.

## What it touches

- **Rule 3.8.** Its Enforced-by names `typeshade sync`, which writes a view for a `*.shade.ts`
  only. It becomes `tscc sync`.
- **Rule 3.9.** Its Enforced-by names `typeshade check` among the paths `linkProgram` serves. It
  becomes `tscc check`.
- **Rule 12.7.** "a program the compiler accepts must draw no error in the editor or in
  `typeshade check`" becomes `tscc check`. What the rule requires does not move, but its text
  does, so Doorstop marks the rule and the surface sections that explain it for review
  (`reqs/README.md`).
- **Rule 13.10.** The deprecation option on the command line, `typeshade check --deprecations`,
  becomes `tscc check --deprecations`.
- **Surface §64.** The setup's `"prepare": "typeshade sync"`, the first line of the host view it
  shows, and the paragraph on a clean checkout (`typeshade sync` writes every view first;
  `typeshade sync --check` fails on one that is missing or stale).
- **Surface §68.** "How each path reads the files": `typeshade sync` reads the imports from
  disk, and `typeshade check` checks a shader module a checked file imports.
- **Exports, codes and examples: none.** `checkDocuments`, `checkOpenDocument` and
  `CheckDiagnostic` keep their shapes, `source` included. No diagnostic names the command. The
  set of examples does not change; the comments of `examples/imported-noise.shade.ts` and
  `examples/_shade.ts` name `typeshade sync` and follow, and the emit goldens show that no
  emitted byte moved.

The code:

- `package.json`: the `bin` key `typeshade` becomes `tscc`, and so does the script of that name.
  `scripts/publish-manifest.ts` derives the tarball's `bin` from the same map and does not
  change. `src/cli/bin.ts` still finds its version by the manifest's `name`, which stays
  `typeshade`.
- `src/cli/run.ts`: `USAGE`, the prefix of each error, and `sync --check`'s remedy.
- `src/compiler/ts/host-face.ts`: the view's first line.
- The comments that name the command, in `src/cli/`, `src/language-service/`,
  `src/compiler/ts/`, `src/vite.ts`, `scripts/user-journey.ts` and `journeys/`.

The prose that names the command, which `bun run docs:impact` lists for the implementing pull
request: `README.md` ("Checking shaders from the command line", with the `npx -p` form and the
line on a project that also has `@tscc/tscc`, and the host-import setup), `AUTHORING.md` ("The
CPU oracle"), `AGENTS.md` (the `src/cli/` row), `RELEASING.md`, `docs/dx.md`,
`docs/use-typeshade-plan.md`, `docs/language-service-api.md` and `journeys/README.md`; `reqs/`
follows by `bun run reqs:sync`. `CHANGELOG.md` has nothing to rename: the command was never
published, and `[Unreleased]` does not name it. The proposals that name `typeshade check` or
`typeshade sync` (0007, 0009, 0010, 0016, 0017, 0022) record what was decided then, and stay.

The tests that will pin it:

- `src/cli/run.test.ts`: the usage text and the prefix of each error read `tscc`, and the
  spawned `bin.ts` answers `--version` as before.
- `src/vite.test.ts`: `sync --check` reports a missing and a stale view with `run tscc sync.`
- `src/publish-manifest.test.ts`, D6: `package.json` declares one command, `tscc`, and the
  derived manifest maps it to the emitted `bin.js` under `dist/`.
- `bun run gate:journeys`: `journeys/_host-import`'s `prepare` runs `tscc sync` after a plain
  `npm install` of the packed tarball. That proves npm links the command under its new name,
  and that the views it writes are the ones `tsc` reads.

## What it owes downstream

- **typeshade.github.io.** No page of the site names the command at its pin (`9fbe5ef`):
  `typeshade check`, `typeshade sync` and `npx typeshade` appear nowhere outside `vendor/`. On
  the pin that carries this change:
  - the Korean translation of "The CPU oracle" (`content/guide/ko/the-cpu-oracle.md`) is
    translated again if `bun run check:guide` lists it, since the English names `tscc`;
  - the rule pages print the new text of Rules 3.8, 3.9, 12.7 and 13.10 from the pin, with
    nothing to edit: no page of the site records a fingerprint of any of the four
    (`READ_AGAINST` in `src/lib/design-rules.ts`, and `content/guide/ko/rules.json`);
  - any copy the site adds for the host-import setup or for CI writes `tscc`, and
    `npx -p typeshade tscc` where the package may not be installed.
- **vscode-typeshade.** Nothing there runs the command. These name it:
  - `packages/tsserver-plugin/src/fixtures.ts`: `HOST_IMPORT_PROJECT` reproduces the host view
    byte for byte, so its first line becomes `` `tscc sync` rewrites it ``, and its doc comment
    names `tscc sync`;
  - the skill's host setup, `plugins/typeshade/skills/typeshade/SKILL.md` and
    `references/host.md`, whose line becomes `"prepare": "tscc sync"`;
  - `docs/design.md`'s paragraph on the host view and `docs/agents.md` §3.1 (the `check` tool),
    where they name the command;
  - the comments of `packages/mcp-server/src/format.ts` and `tools.ts`.

## What comes next

`tscc` keeps the two commands it has. A command that writes `.wgsl` and `.glsl` files, which a
compiler's name may suggest, is not part of this change; if one comes, it is its own proposal.

## Decisions for the reviewer

Accepting this proposal accepts each of these. Each can be changed before acceptance without
touching the rest:

1. The command is `tscc`, with the cost measured under Why: `npx tscc` needs `-p typeshade`
   where the package may not be installed, and a project that also depends on `@tscc/tscc` runs
   that package's command.
2. `tscc` replaces `typeshade` as the command, with no second name, since no release has shipped
   one.
3. The package, the import specifiers, the directive, the host view's name, `moduleSuffixes`,
   the Vite plugin and a diagnostic's `source` keep `typeshade`.
4. The host view's first line keeps "Generated by typeshade", which the Vite plugin writes too,
   and names `tscc sync` as what rewrites it.
5. Only the name moves: `check` and `sync`, their options, their output and their exit statuses
   stay as they are.
